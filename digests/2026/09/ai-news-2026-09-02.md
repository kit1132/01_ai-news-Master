### 1. Claude Fable 5.1 / Mythos 5.1 が GA — キャッシュ読み込みが1/4になり、履歴を書き換える実装は 400 で落ちるようになった

**要点**: Anthropic が 9/1 に Claude Fable 5.1 を全顧客向けに出した。基本料金は Fable 5 と同額のままキャッシュ読みだけ $1.00 → **$0.25/MTok**。同時に破壊的変更が3件入り、**強制ツール呼び出しと会話履歴の書き換えは 400 エラー**になった。長時間エージェントの単価前提と実装前提が同時に変わる。

**詳細**: モデル ID は `claude-fable-5-1`（Mythos 5.1 は `claude-mythos-5-1` で Project Glasswing 参加者限定）。context 100万トークン・最大出力 128k・adaptive thinking 常時オンは Fable 5 と同じで、料金は入力 $10 / 出力 $50 / 5分キャッシュ書き込み $12.50 / 1時間 $20 も据え置き。キャッシュ読みだけが基本入力の 0.1倍から **0.025倍**に下がった（他の Claude モデルは 0.1倍のまま）。Batch は入力 $5 / 出力 $25。

破壊的変更は3件ある。

- `tool_choice` の `any` と `tool`: 400 `invalid_request_error` を返す。`auto`（既定）と `none` は変更なし。スキーマを強制したい場合は strict tool use か structured outputs へ移す
- thinking ブロックのモデル束縛: Fable 5.1 は旧モデルの thinking ブロックを読めるが、**逆は読めない**。読めないブロックは API が黙って落とす（`thinking-binding-controls-2026-08-01` ヘッダを付けると `input_transformations` に報告される）
- 過去ターンの編集: `system` プロンプト・`tools` 配列・過去メッセージのいずれかを書き換えると、以後の thinking ブロックが無効になり 400 を返す。⚠️ **2026-08-31 以降に作成されたアカウントでは強制適用**され、それ以前のアカウントは `prefix_mismatch_behavior` を明示したときだけ作動する

コード変更なしで挙動が変わる点も6件挙がっている。並列ツール呼び出しが減って1ターン1呼び出しになりやすい／ツール実行中の進捗テキストが減る／`low` effort で検索を呼ばず記憶から答えがち／散文が密になる／チャットでの装飾が減る／小さな修正でもファイル全体を書き直しがち。Anthropic 自身が「回答品質は落ちないがトークン・往復・実時間のコストが増える」と明記している。

追加された beta は3つで、いずれもプロンプトキャッシュを壊さずに状態を変えるためのもの。会話途中の effort 変更（`mid-conversation-output-config-2026-07-01`）、1ターンだけ有効な system メッセージ（`mid-conversation-system-clear-at-2026-08-21`）、進捗更新をテキストで受け取る `thinking.display: "updates"`（`thinking-display-updates-2026-08-18`）。Fable 5 と同じく **30日データ保持が必須**で、明示的な許可なく ZDR では使えない。Bedrock・Claude Platform on AWS・Google Cloud・Microsoft Foundry でも同日提供。

⚠️ 二次記事は「典型的な負荷で Fable 5 比 25% 安い」と書いているが、これは**一次には無い推計**である。一次が保証しているのはキャッシュ読み単価だけで、削減幅はキャッシュ読みの比率次第になる。

### 2. Claude Code 2.1.257 — auto モードがクラウド認証情報の取得を自動承認しなくなった

**要点**: Claude Code 2.1.257 が 9/1 に出て、auto モードに Containment Escape ルールが入った。**クラウドメタデータからの認証情報取得・egress 回避・テナント跨ぎのアクセスは、環境が想定内と示さない限り自動承認されない**。auto モードを常用している環境では、これまで無言で通っていた操作が今日から止まる。

**詳細**: 権限境界の変更が他にも入っている。作業ディレクトリ外の初回ファイル読み込み前に一度だけ確認が入り、`permissions.blockReadsOutsideWorkingDirectories` で読み取り自体を禁止できる。`--add-dir` / `additionalDirectories` は UNC 共有や `/net/<host>` 自動マウントを触る前に拒否するようになった（Windows ではドライブレターを割り当てて使う）。Cowork と claude.ai のクラウドセッションでは、**自分のものではない artifact の読み込みは auto モードでも必ず確認**を挟む。プラグインが宣言したパスが symlink の場合はエラーで拒否する。

モデル関係では **Fable 5.1 が既定の Fable モデル**になった。ただしゲートウェイ経由のセッションでは `fable` / `best` は当面 Fable 5 に解決される（Fable 5.1 未設定のゲートウェイが拒否するため）ので、使うには `/model` で明示的に選ぶ。設定系では `timeFormat` と `timeZone`（12時間 / 24時間 / 24時間 UTC / strftime パターン）、サブエージェントのモデル指定を全階層に強制する `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`、`/effort` の `s`（当該セッションのみ変更）が加わった。

⚠️ **`stable` タグは `2.1.236` のまま据え置きで、`latest`（2.1.257）との差が21版に開いた**（`registry.npmjs.org` の `dist-tags` 実測）。8/28 の 2.1.251 に入った権限境界の修正群（symlink 差し替えによる作業ディレクトリ外の読み書き・marketplace プラグインのディレクトリ外参照・symlink 経由の Grep / Glob での deny 無視）は、stable 固定の組織へ**5日経っても届いていない**。なお `next` は 2.1.257 で `latest` に再合流した。⚠️ `2.1.253`〜`2.1.256` は npm の `time` にも changelog にも無い欠番で、取りこぼしではない。

### 3. GitHub Copilot のモデルアクセスが請求元組織だけで決まるようになった

**要点**: GitHub が 8/31 に、複数組織で Copilot シートを持つ利用者のモデルアクセスを**請求を負担している組織の設定だけ**で決めるよう変更した。従来は所属するどれかの組織が有効にしていれば使えたので、**今日から使えるモデルが減る利用者が出る**。告知時点で適用済みで、猶予期間はない。

**詳細**: 請求元は Copilot features ページの「Usage billed to」で確認できる。Copilot へのアクセスが enterprise またはその配下組織だけから来ている利用者は影響を受けない。対象は GitHub Team プラン。⚠️ 告知には**どのモデルが対象かの記載がない**ため、影響の有無は各自が請求元組織の model policy を見て確かめるほかない。9/1 に完了した global model policy の全 enterprise 適用と合わせると、**モデル選択の決定権が個人・所属組織から請求元組織へ寄る**流れが2日続けて発効したことになる。
