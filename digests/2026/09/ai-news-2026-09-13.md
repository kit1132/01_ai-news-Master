### 2. Claude Code 2.1.269 が権限ルールの適用範囲を変えた — `!` 否定ルールが書いた設定ソースの中だけに閉じる

**要点**: 前日は版番号しか分からなかった `2.1.269` の changelog が出た。`!` で始まる deny / ask ルールが設定ソースをまたいで効く挙動が修正され、組織の権限設計は前提が変わる。

**詳細**: 権限とサンドボックスまわりの修正が今回の中心である。

- 権限ルール: `!` で始まる deny / ask ルールは、それを書いた設定ソースの中だけに適用されるようになった。単独の `!` 否定は無視される
- 書き込み経路: `Edit()` の deny ルールと書き込みパス検査が Bash の `tee` の出力先にも掛かるようになり、`Bash(tee:*)` の allow だけでは作業ディレクトリ外へ書けなくなった
- プラグイン展開: セッション用に展開したプラグインアーカイブが他のローカルユーザーから読める問題、アーカイブの world-writable ビットを引き継ぐ問題、再展開時に古いファイルが残る問題が直った
- 新コマンド: `claude plugin eval` がプラグインの eval スイートを Claude Code に対して実行し、JSON と HTML のレポートで採点する。`/output-style [name]` は Remote Control とクラウド / headless セッションでも使える
- 環境変数3種が追加された: `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（1〜256・Workflow の同時エージェント上限）／ `OTEL_METRICS_INCLUDE_REPOSITORY`（OTel のメトリクスに `vcs.*` を付与）／ `CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS`（LLM gateway の `/v1/models` 探索・既定3秒）
- prompt cache: 出力トークン上限で切れて自動再開した次のターンでキャッシュが部分無効化される問題と、中断後の resume で過去コンテキストの再送形が変わりキャッシュ再利用が落ちる問題が直った
- npm の `dist-tags` は `{stable: 2.1.236, latest: 2.1.269, next: 2.1.270}` である。**`2.1.270` は 9/12 18:52 UTC に publish されたが changelog に無く内容は未確定**

### 3. GitHub Copilot の code review が指摘を自動解決しシェル実行で検証を始めた — Lite の既定が単一エージェントから合議に変わった

**要点**: Copilot code review は、指摘に対応するコミットを push すると再レビュー時にそのスレッドを自分で解決するようになった。Lite も複数エージェントの合議に変わり、返ってくる指摘の質と件数が変わる。

**詳細**: 9/11 の changelog が挙げる変更は3点である。

- 自動解決: 指摘に対応する新しいコミットを push すると、再レビュー時に Copilot が該当コメントを解決する。手動でのスレッド解決が要らなくなった
- 検証の強化: ビルドコマンド・テスト・スクリプト・API 呼び出しといったシェル実行をレビュー中に使ってコードを検証するようになった
- Lite の合議化: 単一エージェントのレビューから、複数のエージェントが観点を持ち寄る ensemble 方式へ変わった。GitHub の測定では高深刻度の指摘の対応数が **47%** 増、中が31%増、低が11%増で、コストは約8%減とされる

Copilot の提案を適用するときのコミットメッセージも、自動入力の定型文から内容に即した文面へ変わった。⚠️ **記事は対象プランを明示していない**。
