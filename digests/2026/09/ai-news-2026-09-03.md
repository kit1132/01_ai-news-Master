## 今日のハイライト

### 1. Copilot code review が PR を承認できるようになった — レビュー承認が「人が押すもの」でなくなる

**要点**: GitHub が Copilot のレビューに、merge requirement へ数える承認の提出を許した。承認人数で品質を担保していた運用は、既定オフのまま置くか有効化するかを組織として決める必要がある。

**詳細**: 9/1 公開で public preview。対象は Copilot Pro / Pro+ / Max / Business / Enterprise。既定では Copilot は承認せず、管理者が明示的に有効化しなければ動かない。全レビューの overview コメントには merge 可否を示す「承認アセスメント」が入るが、**アセスメント単体は merge requirement に数えない**（人が読んで判断する情報にとどまる）。実際の承認提出を許すかどうかは3階層で設定する。

- enterprise: 組織単位の判断を許可／拒否する、または全社で無効化する
- organization: 全社有効化・リポジトリ単位・特定リポジトリのみ・無効化から選ぶ
- repository: 承認のオン／オフに加え、**Copilot が承認できるファイルパスを制限**できる

新規コミットが push されると Copilot の承認は自動的に取り消される（人間のレビュアーと同じ挙動）。

- https://github.blog/changelog/2026-09-01-copilot-code-review-can-now-approve-pull-requests

**要点**: Copilot 全 IDE で Fable 5.1 が使えるようになったが、Business / Enterprise は管理者がポリシーを有効化するまで使えない。ZDR を続けるには年末までの暫定免除か **Enterprise Frontier Safeguards** が要る。
