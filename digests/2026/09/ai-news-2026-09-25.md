### 1. [料金] Anthropic が出力前の拒否のうち3カテゴリを課金対象にした — 「出力ゼロで拒否されたリクエストは無料」の前提が崩れた

**要点**: Anthropic が 9/24 から、出力前に拒否されたリクエストのうち `stop_details.category` が `bio` / `frontier_llm` / `reasoning_extraction` のものを通常単価で課金するようにした。拒否は無料という前提で組んだコスト試算とリトライ設計を引き直す必要がある。

**詳細**:

- 対象プラットフォーム: Claude API・Amazon Bedrock・Claude Platform on AWS・Google Cloud・Microsoft Foundry の全経路
- 対象モデル: Fable 5.1 / Fable 5 / Opus 5.5 / Opus 5
- 課金方法: 実行したモデルの通常単価で課金する。`content` は空で、トークン数は `usage` に出る
- 課金しないもの: 上記以外のカテゴリと `null`。ただし出力前の拒否はすべてレート制限にカウントされる
- 出力途中の拒否: 入力と、それまでにストリームした出力を課金する。fallback を使った場合、発端の拒否が途中拒否か課金カテゴリなら fallback 側のリクエストと別に課金される

⚠️ Anthropic は「2026年9月時点で誤検知率が低いと測定できたカテゴリ」と書き、**一覧は今後変わりうる**としている。同日、Claude Code `2.1.282` の `claude-api` スキルもこの課金方式に合わせて更新された。前日 9/23 には cache diagnostics が beta を抜け、`cache-diagnosis-2026-04-07` ヘッダーが不要になった。

### 2. [破壊的変更+セキュリティ] Claude Code `2.1.281` / `2.1.282` で権限の穴が塞がれ、スキル名前空間と self-hosted runner の渡し方が変わった — 同時に `stable` がようやく `2.1.273` へ進んだ

**要点**: Anthropic が 9/23〜9/24 に Claude Code `2.1.281`・`2.1.282` を出し、auto モードの権限判定と managed settings の穴を多数塞いだ。`anthropic-skills:` / `claude-ai:` 名前空間のローカルスキルは読み込まれなくなり、self-hosted runner のシステムプロンプトはファイル渡しになる。

**詳細**:

- npm `dist-tags`: `{stable: 2.1.273, latest: 2.1.281, next: 2.1.282}`（09-25 実測）。**`stable` は 15日据え置いた `2.1.267` から `2.1.273` へ進んだ**が、Opus 5.5 を既定にした `2.1.280` 以降は依然 stable に未到達
- `2.1.282` の破壊的変更:
  - `Skill(anthropic-skills:*)` / `Skill(claude-ai:*)` の allow ルールは claude.ai から同期したスキルだけを覆う。同名前空間のローカルのスキルフォルダー・コマンドファイル・ワークフローコマンドは読み込まれない
  - 名前が `anthropic-skills` / `claude-ai` の MCP サーバーはスキルとプロンプトを列挙しない（ツールは動く）
  - project / local settings の OpenTelemetry 有効化・送信先・本文取得の変数（`CLAUDE_CODE_ENABLE_TELEMETRY`・`OTEL_LOG_*` 等）を無視する
- `2.1.282` の権限修正: managed の `allowManagedPermissionRulesOnly` 下でリポジトリ・ユーザー・`--add-dir` のスキルやプラグインが `allowed-tools` で自分のツールを事前承認できた問題、真偽値ロックキーの型違いが無視されていた問題、managed の `permissions` / `autoMode` ブロックが1値の不正で丸ごと無視されていた問題を直した
- `2.1.281` の権限修正: `rm -rf "$(pwd)"` のようなコマンド置換結果への再帰削除は、auto モードでも Bash の allow ルールに一致しても確認を出す。NUL バイトを含む権限ルールがワイルドカード化していた問題と、`claude --bg` が未信頼ディレクトリでフックを実行できた問題も直した
- `2.1.281` の破壊的変更: self-hosted runner がシステムプロンプトをファイルで渡すようになり、`--system-prompt` / `--append-system-prompt` を付け足すラッパーや `command` フックは `--system-prompt-file` / `--append-system-prompt-file` へ移す必要がある
- auto モード: サーバー側分類器の環境では読み取り専用・サンドボックス内のシェルコマンドも審査待ちになる。`2.1.282` からは Anthropic API 直結かつテレメトリ無効でもサーバー側分類器が既定になる（`CLAUDE_CODE_AUTO_MODE_SERVER=0` で戻せる）

- https://code.claude.com/docs/en/changelog
- https://www.npmjs.com/package/@anthropic-ai/claude-code

### 3. [新機能] GitHub が Copilot code review の個人設定ページを全プランに開き、Enterprise の既定 effort を一括指定できるようにした — 9/28 の既定 Balanced 化の前に、自分と組織で上書きできるようになった

**要点**: GitHub が 9/23 に Copilot code review の個人設定ページを Pro〜Enterprise の全プランで GA にし、自動レビューの契機と既定の review effort（Lite / Balanced）を個人で選べるようにした。Enterprise 管理者は既定 effort を1つ決めて組織・リポジトリへ継承させられる。

**詳細**:

- 個人設定: プロフィール → Copilot settings に「code review」ページ。これまでは Pro / Pro+ / Max だけで項目も限られていた
- 自動レビューの契機: PR 作成時・共同作成時・ドラフトの ready 化時から選ぶ。新しい push とドラフト PR はそれぞれ別のトグルで制御する
- 既定 effort: 個人が Lite / Balanced を選び、自分が依頼したレビュー（自動を含む）に適用される
- Enterprise: 既定 effort（Lite / Balanced / GitHub 既定）を1つ設定でき、組織とリポジトリが継承し、下位で上書きできる（GA）

- https://github.blog/changelog/2026-09-23-copilot-code-review-more-ways-to-request-and-configure-reviews
