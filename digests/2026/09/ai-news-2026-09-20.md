### 3. Claude Code の auto モード既定が4日で反転した — classifier のオーバーヘッド課金が消える

**要点**: `2.1.278` が auto モードの既定をサーバー側 classifier へ戻し、**classifier のオーバーヘッドを課金しなくなった**。4日前の `2.1.273` はローカル classifier を既定にしていたので、`CLAUDE_CODE_AUTO_MODE_SERVER` の意味が反転している。

**詳細**: `2.1.278` は 9/19 01:48 UTC に publish された。本版の変更は2行だけで、どちらも auto モードの課金と可視化に関わる。

- 対象は Claude API と Enterprise のユーザー、および Bedrock / Vertex / Foundry / ゲートウェイ経由の利用で、既定がサーバー側 classifier になる。サーバー側は classifier のオーバーヘッドを課金しない
- 離脱は `CLAUDE_CODE_AUTO_MODE_SERVER=0`（Bedrock / Vertex / Foundry / ゲートウェイのみ）。課金されるフォールバックに落ちた場合は警告が出る
- `/status` に `Auto mode server` 行が追加され、当該セッションの classifier がサーバー側で走っているかを確認できる
- 専用ドキュメント `code.claude.com/docs/en/auto-mode-classifier-billing` が新設された

⚠️ **`2.1.273`（9/15）は同じ対象に対して逆の既定を置いていた**。当時は Bedrock / Vertex / Foundry で当面ローカル classifier を既定とし、サーバー側へ回すには `CLAUDE_CODE_AUTO_MODE_SERVER=1` を設定する形だった。9/15 に `=1` を明示設定した組織は、本版以降その指定が既定と同じ意味になる。逆に `=1` のまま離脱したつもりでいると意図と逆になる。

⚠️ この変更は stable 固定の組織にはまだ届いていない。npm の `dist-tags` は `{stable: 2.1.267, latest: 2.1.278, next: 2.1.278}` で、`stable` は 9/9 publish の `2.1.267` から**11日連続の据え置き**、未到達は `2.1.268`〜`2.1.278` の11版ぶんである。
