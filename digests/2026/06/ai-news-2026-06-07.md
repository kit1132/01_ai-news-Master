## 最優先

### Claude Code v2.1.166 / v2.1.167（6/6 stable）— fallbackModel と cross-session 権限ハードニング
- 昨日のダイジェスト時点では v2.1.165（バグ修正のみ）まで反映。同日 **v2.1.166 が 21 項目の大型リリース**、続けて **v2.1.167 が同日 stability パッチ** として公開された
- **`fallbackModel` 設定追加**: プライマリモデルが overloaded / unavailable のとき、**最大 3 つのフォールバックモデル**を順に試行。`--fallback-model` がインタラクティブセッションにも適用されるように
- **deny rule の tool-name 位置に glob 対応**: `"*"` で全ツール拒否可能。allow rules は非 MCP glob を拒否、deny rules 中の未知ツール名は起動時に警告
- **🔒 Cross-session messaging のハードニング**: 他 Claude セッションから `SendMessage` 経由で中継されたメッセージは **user authority を持たないように**。receivers は中継された permission request を拒否、auto mode もブロック（マルチセッション運用時の権限昇格対策）
- `MAX_THINKING_TOKENS=0` / `--thinking disabled` / モデル毎 thinking トグル が、Claude API 経由で既定 thinking 有効モデルでも thinking を無効化可能（3P プロバイダ挙動は不変）
- **fallback モデルでターン 1 回自動リトライ**: API が非リトライ可能エラーを予期せず返したとき。auth / rate-limit / request-size / transport は即時表面化
- `claude update` がダウンロード前にターゲットバージョンをアナウンス（無言進行を解消）
- `claude agents` で URL タイピングにより最初のプロンプトに含むセッションを絞り込み
- 修正抜粋:
  - 処理不能画像送信時の「image could not be processed」エラー再発 + 余分なトークン消費
  - 起動時 worker registration での短時間バックエンド停止が remote session を永久ハングさせる問題
  - JetBrains IDE（IntelliJ / PyCharm / WebStorm 等）2026.1+ の terminal ちらつき（synchronized output 有効化）
  - Kitty keyboard protocol 端末（WezTerm, Ghostty, kitty）で Shift+非 ASCII（例: Shift+ä → Ä）が脱落する問題
  - Windows PowerShell コマンド検証が killed プロセスの子が出力 pipe を保持し続けて time budget を遥かに超えてハングする問題
  - macOS で daemon 落下後 `claude --bg-pty-host` が CPU 100% で残留
  - voice mode が `/voice` トグル後に古い auth check をクリアするのに `/login` を要求していた問題
  - managed settings の無効エントリ 1 件で残りの有効ポリシーが silently disable される問題
  - managed-settings の `allowedMcpServers` / `deniedMcpServers` 述語が `${VAR}` 参照で match しない問題
  - background agent セッションが worktree 内に入った状態で `claude agents` から再開すると "No conversation found" でクラッシュループする問題
  - `/doctor` が remote session 内で誤って "Not inside a remote session" を fail 表示する問題
- ソース: https://code.claude.com/docs/en/changelog / https://www.claudeupdates.dev/version/2.1.167

### ChatGPT「Dreaming V3」メモリ + Lockdown Mode が Plus/Pro へ rollout 開始（6/4-5）
- OpenAI が **「Dreaming V3」** を 6/4 から Plus/Pro（US）にロールアウト開始。**手動 curate された saved-memories リストを廃止**、過去会話を横断的に読む **バックグラウンド合成プロセス** がユーザの記憶を自動更新
- 例: "you're going to Singapore in July" → 旅行終了後に "you went to Singapore in July 2026" へ自動書き換え
- Plus / Pro は **メモリ容量 2 倍**。**reviewable memory summary page** が追加されレビュー可能化。Free / Go 国際版は数週間内に展開予定
- 同時に **Lockdown Mode** が全ログインユーザに opt-in 提供開始。Web / 外部サービスへのアクセスを制限し、**prompt injection 経由のデータ exfiltration** を低減（高リスク利用者向け、Free / Go プランへも順次拡大）
- ソース: https://help.openai.com/en/articles/6825453-chatgpt-release-notes / https://www.techtimes.com/articles/317840/20260605/chatgpt-memory-dreaming-update-openai-rewrites-personalization-engine-limits-audit-trail.htm / https://techjacksolutions.com/ai-brief/chatgpt-update-openais-dreaming-system-gives-plus-and-pro-us/

### Cursor 3.7（6/4-5）— Design Mode が canvas 対応 + Context Usage Report + SDK 強化
- 6/4 リリースの **Cursor 3.7** で Design Mode が canvas 内に拡大、6/5 にさらに改良
- **Design Mode in canvases**: canvas 上で UI 要素を直接選択・注釈して agent に編集指示。テキスト記述よりも迅速に反復可能。**音声でも指示可能**
- **Context Usage Report (Context Explorer)**: agent の context 使用量を canvas 上のインタラクティブレポートとして可視化。system prompt / tool definitions / rules / skills 毎のトークン内訳
- **SDK 大型更新** (TypeScript / Python):

  - 独自関数を **tool として agent に expose**
  - ローカル tool call を **auto-review にルート**
  - **subagent を任意深度で nest** 可能
  - インストール: `npm install @cursor/sdk` / `pip install cursor-sdk`
- ソース: https://cursor.com/changelog / https://cursor.com/changelog/canvas-improvements / https://cursor.com/changelog/design-mode-improvements

## 業界動向

- **Claude Code の cross-session 権限ハードニングが multi-agent / multi-session 運用の前提条件を変更** — `SendMessage` 経由のメッセージから user authority を剥がしたことは、Claude Code on the web / 並列 agent / Skill から SendMessage を活用するチームに即時影響。auto mode 中の関連 deny を組織方針に組み込むのが現実的
- **`fallbackModel` が「Claude API 偏在」から「マルチモデル resilience」への第一歩** — 最大 3 段フォールバック宣言は、Bedrock / Vertex / Foundry の 3P 経路や Anthropic の API キャパシティ事情を front-load した運用パターンを示唆。GitHub Copilot の「複数モデル picker」化と並走
- **ChatGPT Dreaming V3 + Cursor Context Report が「文脈ガバナンスの可視化」競争** — OpenAI は「自動で更新される memory + reviewable サマリ」、Cursor は「token がどこに使われたか」のインタラクティブレポート。チームに導入する側の **「context のオーディタビリティ」要求** が浮上
- **Cursor Design Mode が「Figma 不要」のフロントエンド agent UX を加速** — 音声 + canvas 注釈で UI 編集を直接指示する流れは Claude Code（Plan/Verify skill）/ Devin Review / Copilot Canvases と並列の「**human-in-the-loop の解像度**」競争
- **OpenAI Lockdown Mode + Claude Enterprise admin 権限委譲** が同時期 — 大企業 IT / セキュリティチームが prompt injection / 権限境界の懸念を主要購買基準にしている兆候。両社とも「商用速度」と「安全規制対応」を抱き合わせ
