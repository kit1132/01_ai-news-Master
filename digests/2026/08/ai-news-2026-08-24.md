### 1. Cloudflare が Chromium を使わないエージェント専用ブラウザを出していた — エージェントに Web を見せるコストの前提が変わる

**要点**: Cloudflare が 8/6 に Kitesurf を公開していたことを本日はじめて検出した。V8 isolate 上で動き Chromium 比で CPU・メモリが3〜7分の1、しかも CDP 互換なので既存の Playwright / Puppeteer / MCP 統合は書き換えずに切り替えられる。

**詳細**: Kitesurf は Cloudflare Workers の V8 isolate 内で完結するブラウザランタイムで、Browser Run サービス経由で提供される。人間向けの機能（タブ・テーマ・ピクセル単位の忠実なレンダリング）を落とすことで、スクリーンショットや HTML 抽出といったエージェントの定型作業に必要な分だけを残している。Cloudflare は開発期間を12週間としている。

- 互換性: **Chrome DevTools Protocol を話す**ため、既存の Puppeteer / Playwright / CDP / MCP ベースの統合は `browser=kitesurf` を指定するだけで切り替えられる
- 資源効率: スクリーンショットと HTML 抽出で **CPU・メモリとも Chromium の3〜7分の1**
- 速度: 同じ作業の所要時間は **Chromium の約1.7倍**（遅い側）。ラスタライズと画像エンコードを最適化中とされる
- 提供条件: **beta・無料**、アカウント単位の上限あり
- 非対応: 動画再生、WebGL、実 TLS フィンガープリントを要するボット検査の通過、永続状態を要する認証済みセッション

⚠️ 本項は **18日遅れの初検出**である。Anthropic が 8/19 に computer use を GA・browser use を投入し `web_search` / `web_fetch` にドメイン制限を入れた直後の時期にあたり、エージェントの実行基盤を選び直す判断材料が3週間近く抜けていた。原因は到達性ではなくソース未登録で、B-042（Windows Command Line）・B-037（Meta）と同型の欠落として **B-043 を起票**した。⚠️ `blog.cloudflare.com` / `developers.cloudflare.com` はいずれも本日の実測でゲートウェイ拒否のため、**上記の数値・条件はすべて二次一致で採っており一次未確認**である。

### 2. Copilot CLI のローカルプラグインが編集即反映になった — プラグイン開発で `/plugin update` を挟む手順が消える

**要点**: GitHub が 8/23 に Copilot CLI の pre-release v1.0.81-8 を公開し、ディレクトリ由来のプラグインを実体から直接読むよう変えた。編集が `/restart` か新セッションでそのまま効くので、自作プラグインの反復に更新コマンドを挟む必要がなくなる。

**詳細**: 変更は3項目のみの小さな版だが、いずれも日常の操作に触れる。

- パス由来のプラグイン（ローカルのディレクトリ marketplace）が**実ディレクトリからライブで読み込まれる**ようになり、編集は `/restart` または新セッションで反映される。`/plugin update` は不要
- `--add-dir` で追加したディレクトリからも **skills と custom agents が探索される**ようになった
- **Grok 4.6 で `xhigh` reasoning effort が使える**ようになった。Cursor 側は 8/13 の Grok 4.6 提供開始時点で effort 4段（`xhigh` / `high` / `medium` / `low`）を持っていたので、Copilot が追いついた形になる
- アカウントからサインアウトすると**キャッシュ済みのエンタープライズ管理設定が破棄される**よう修正された。従来はサインインし直しても旧ポリシーが再適用されることがあった

安定版は **v1.0.80（8/14）のまま10日間据え置き**で、上記はいずれも pre-release 側の変更である。
