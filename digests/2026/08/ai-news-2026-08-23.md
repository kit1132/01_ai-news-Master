### 2. Claude Code v2.1.239 が Bedrock の二重課金バグを修正した — 原因不明の課金増は仕様ではなくバグだった

**要点**: Anthropic が 8/21 に v2.1.239、8/22 に v2.1.240 を公開した。プロキシ経由 Bedrock で課金対象の API 呼び出しが黙って倍増する不具合が直り、心当たりのない Bedrock 課金増は仕様ではなくバグだったと確定した。

**詳細**: v2.1.239 は約65項目の大型リリースで、実務に効くのは次の4点。

- Bedrock ストリーミングがレスポンスの `Content-Type` ヘッダを削るプロキシの背後で失敗し、**毎ターン非ストリーミングで再実行されて課金 API 呼び出しが倍**になっていた不具合を修正した
- `/cost`・ステータスライン・`--max-budget-usd` のコスト見積もりが、データレジデンシー Workspace の **US-only-inference の 1.1倍プレミアム**を含むようになった
- `/claude-api upgrade` が追加され、Python プロジェクトの `anthropic` 0.x → 1.x 移行を実行できる（ハイライト3の SDK に対応）
- Claude Code on the web で、Bash などのツールから非 API の anthropic.com ホスト（www・docs 等）へ出る通信がセッションのネットワークプロキシを通るようになり、環境の許可ドメイン設定が効くようになった

このほか Alpine / musl ビルドで画像ペースト・クリップボード・音声キャプチャが musl ビルドのアドオンとして読み込めるようになり、Windows でクロスセッションメッセージング（`SendMessage` / `ListAgents`）が macOS / Linux と同様に使えるようになった。利用上限メッセージは月次上限を使い切った場合にセッション上限・週次上限のリセット時刻も表示する。v2.1.240（8/22）は bug fixes のみ。

- https://code.claude.com/docs/en/changelog

### 3. Anthropic Python SDK が v1.0 になり httpx を捨てた — 既存の Python 連携は無変更では上がらない

**要点**: Anthropic が 8/20 に Python SDK v1.0 を出し、HTTP 層を httpx から httpx2 へ移した。Python 3.10 未満と Text Completions API、Messages の temperature / top_p / top_k が同時に消え、無変更での追随はできなくなった。

**詳細**: httpx2 は API 互換のフォークで、カスタム `http_client` / `Timeout` / transport は `httpx2` 側から組む（`DefaultHttpxClient` ヘルパーは変更なし）。httpx をパッチするトレーシング・モックライブラリを使っている場合は、起動時に `httpx2.alias_httpx()` を呼ぶ必要がある。破壊的変更は次のとおり。

- **Python 3.10 以上が必須**になった
- 旧 Text Completions API、Messages メソッドの `temperature` / `top_p` / `top_k`、tool runner のクライアント側 `compaction_control` が削除された
- 非同期クライアントの `.with_raw_response` の結果は `await response.parse()` が必要になった
- `AnthropicBedrock` は AWS リージョン未設定時に `us-east-1` へ暗黙フォールバックせず**エラーを投げる**ようになった

⚠️ 本項は 8/20 付けのエントリだが、8/21・8/22 のセッションがいずれも同じ URL の同日ブロックから取りこぼしていた分である（**同一 URL の同一日付ブロックからの取りこぼしが4日連続**・B-024 に追記）。

- https://platform.claude.com/docs/en/release-notes/api
- https://github.com/anthropics/anthropic-sdk-python/blob/main/MIGRATION.md

## MCP（Model Context Protocol）

  - 原語の改善: ツール呼び出し結果の扱いを標準化し、ツール数が多いサーバーのスケール問題に progressive discovery で対処する
  - SDK 開発体験: 全対応言語での SDK エルゴノミクス・仕様適合テスト・ドキュメントへ投資する
