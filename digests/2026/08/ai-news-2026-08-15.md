**要点**: Alibaba が Qwen3.8-27B の重みを Apache 2.0 で公開した。単体 GPU 級の 27B が OSWorld-Verified 84.3 / Terminal-Bench 2.1 73.0 に達し、「エージェント用途はクラウド API 前提」という置き方が崩れた。

- アーキテクチャ: vision encoder を持つ dense モデルで、Gated DeltaNet と Gated Attention のハイブリッド 64層。テキスト・画像・動画（時間単位の長尺）を入力に取る
- コンテキスト: 262,144 トークンがネイティブ、スケーリングで 1,000,000 まで拡張可
- テキスト系ベンチ: Terminal-Bench 2.1 73.0 / SWE-bench Pro 61.7 / QwenSWEBench 79.0 / LiveCodeBench 90.3 / GPQA Diamond 89.2

### 2. Claude Code v2.1.232 が subagent forking を既定オンにした — サブエージェントの文脈は「渡す」から「継ぐ」へ

**要点**: Anthropic が Claude Code v2.1.232 を公開し、subagent forking を既定オンにした。`subagent_type: "fork"` のサブエージェントが会話とプロンプトキャッシュを丸ごと引き継ぐのが既定になり、「文脈は呼ぶ側が組み立てる」前提が変わった。

**詳細**: 8/13 23:29 UTC 公開。GitHub releases と `raw.githubusercontent.com` の `CHANGELOG.md` の2ソースで最上位一致を確認した（B-024 の手順）。対話セッションでの非 teammate エージェント起動も既定でバックグラウンド実行になる。

- セッション横断: プロンプトに `@` を打つと他の Claude セッションを名前で指名でき、Claude が `SendMessage` で直接届ける。`SendMessage` は生きたセッション1つに完全一致する裸の名前へそのまま配送するようになった（従来は ref での確認を求めた）。同一マシンで名前が衝突すると `name-word-word` 形式の変種が自動で割り当てられる。`/config` に「Dialog expiry」と「Messages from your other sessions」の2行が追加された
- 権限バイパスの修正が3件入った
  - PowerShell: 変数を書き込むパラメータが `$PSDefaultParameterValues` を黙って上書きし、後続コマンドのファイルアクセス先を差し替えられた
  - Windows: Git Bash が Cygwin 形式のシンボリックリンクを追い、パス検証が通常ファイルと誤認していた。リンク経由の書き込みは承認が要るようになった
  - ネストした git リポジトリが親ディレクトリの trust を継承していた。各リポジトリが個別に trust 確認を要する
- GitLab 対応: トークン9系統（`glrt-` / `gloas-` / `glptt-` / `glagent-` / `glimt-` / `glsoat-` / `glcbt-` / `glft-` / `glffct-`）のシークレット redaction が入り、ルーティング可能な `glpat-` / `gldt-` は全体を伏せる。`glab` CLI の設定ストアが `gh` と同じサンドボックスと認証パス保護の対象になり、プラグインマーケットプレースが `gitlab.com` の裸リポジトリ URL（ネストしたサブグループ含む）を `github.com` と同じように clone できる
- 設定名の別名追加: `additionalMarketplaces` / `allowedMarketplaces` が `extraKnownMarketplaces` / `strictKnownMarketplaces` として受理される
- ゲートウェイの boot 検証が厳しくなった。`desktop:` オーバーレイが Desktop 側スキーマで全設定を検証し、未知・不正キーは boot に失敗する。`managed.policies[].match.groups` / `admin.admin_groups` の空要素と不正な `email_domain`（空・`@` や空白やカンマを含む）も、黙って誰にもマッチしない／admin を与える代わりに boot で落ちる
- Fable アクセスを持つ組織で Fable 5 が `/advisor` のアドバイザーとして再提供される（利用クレジットの同意は `/model fable` で行う）

### 3. Copilot CLI が Agent Host Protocol でセッションをホストへ移した — 1セッション1端末の縛りが外れた

**要点**: GitHub が Copilot CLI に Agent Host Protocol（AHP）を入れ、セッションを CLI プロセスからホスト常駐へ移した。複数の端末が同じセッションにアタッチしてターンをライブで追えるようになり、CLI を閉じると作業が終わる前提が消えた。

**詳細**: pre-release v1.0.80-0（8/13 19:37 UTC）で導入され、安定版 v1.0.80 は 8/14 02:28 UTC に「モデル構成の更新」1点で出ている。

- セッション操作: `/ahp sessions|attach|new` がホスト側のセッション一覧を扱う。`/ahp start [port]` / `/ahp stop` / `/ahp restart` で daemon を CLI 内から管理し、`/ahp connect <url>` でホストを動的に足せる
- 入力の扱いはローカルと同じで、Enter が実行中のターンにプロンプトを差し込み、Ctrl+Q が次ターンへキューし、Ctrl+C で取り出す
- Sessions タブがホストごとの健全性を表示し、`h` で複数の AHP daemon ソースを切り替える。複数 CLI がぶら下がっているセッションは「2 clients」のように表示される
- リモート連携: Codespaces は `/ahp codespace <name>` でトンネル転送、Mission Control 環境は Sessions タブに `CLOUD` として出る。ローカル daemon の探索は `COPILOT_AHP_DISCOVER` で制御する
- 接続トークンがログから redaction されるようになり、ホスト側の skills がリレー再接続をまたいで保持される

⚠️ Claude Code v2.1.232 のセッション横断メンションと 24 時間以内に出ており、**両者とも「1セッション＝1端末」を外す方向に動いている**。

- https://github.com/github/copilot-cli/releases/tag/v1.0.80-0
