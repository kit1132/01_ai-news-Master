### 1. Claude Code の承認が本日から分類器任せになり、v2.1.229 / v2.1.231 が同時に出た

**要点**: 本日 8/14 から Pro / Max / Team の新規セッションは auto mode が既定になる。承認の主体が「人がプロンプトを読む」から「分類器がコマンドを審査する」へ移り、既定のまま使う限り止まる箇所が変わる。

**詳細**: auto mode は別モデルの分類器がシェルコマンドと操作を実行前に審査し、要求を超えた権限昇格・未知のインフラへの接続・読み込んだ敵対的コンテンツに誘導された挙動を止める。1,053人の対照試験で危険コマンドの検出率は人手 13.6% に対し 89%。管理は managed settings の `defaultMode` / `disableAutoMode`、分類器の細目は `autoMode` の `environment` / `allow` / `soft_deny` / `hard_deny` で、`allow` を書く際は `"$defaults"` を配列に含めないと組み込みルールが消える。

切り替えに前後して2版が出ている。**v2.1.229**（8/12・30項目超の大型）は auto mode 側で「`CLAUDE_CODE_ATTRIBUTION_HEADER` で帰属ヘッダーを無効化しているユーザーの全ツールコールが失敗する」不具合を直し、**`/commit-push-pr` で `--force` / `--amend` / `--no-verify` 等の危険フラグ付き git / gh コマンドを自動承認しないよう変更**した。サンドボックスはネットワークドメイン一覧の IPv6 リテラルを角括弧表記（`[::1]:443`）にし、曖昧な綴りを fail-closed で弾いて `/doctor` に出すようにした。**v2.1.231**（8/13）は Slack のような事前登録 OAuth クライアントを使う MCP サーバーで redirect URI 不一致によりサインインが失敗する問題の修正1件のみ。⚠️ **v2.1.230 は存在しない。**

### 3. Agent Plugins 1.0 が Copilot 全面で GA — skills と MCP サーバーを1フォルダに束ねる標準

**要点**: GitHub が 8/12 に Agent Plugins 1.0 を VS Code / Copilot CLI / Copilot SDK / Copilot アプリで GA した。クライアントごとに manifest を書き分ける前提が消え、拡張の配布単位がベンダー横断で1つになる。

**詳細**: 仕様そのものは 8/6 公開のベンダー中立標準で、Core Maintainer は Amazon / Anysphere（Cursor）/ Microsoft / OpenAI / Vercel の5社、そこへ Google が加わった。憲章は単一ベンダーが議席の過半を持つことを禁じている。ローンチクライアントは ChatGPT・Codex・Cursor・GitHub Copilot・Kiro・VS Code。

プラグインはアーカイブではなくディレクトリとして定義される。

- `plugin.json`: ルートに置くマニフェスト
- `skills/`: 直下の各サブディレクトリが `SKILL.md` を1つ持つ（省略可）
- `mcp.json`: MCP サーバーの構成（省略可）
- 逆ドメイン名のディレクトリ: `com.github.copilot/` のようにクライアント固有データを入れる

GitHub 側は全 Copilot プランで GA し、プラグインのガバナンス機能は Business / Enterprise が対象。⚠️ **v1.0.0 には権限モデル・サンドボックス・署名検証・シークレット機構のいずれも無く、すべて future work とされている。** 配布可能になったこととガバナンスが揃ったことは別である。⚠️ **Anthropic は Core Maintainer にもローンチクライアントにも入っていない。** Claude Code のプラグインは引き続き独自のマーケットプレース機構で、v2.1.229 でも `command` ソース（ローカルコマンドがプラグインディレクトリを出力し、毎セッション再解決される）という独自方向の追加が入っている。
