### 1. Claude Code v2.1.221 が 10 日ぶりに出た — 承認プロンプトを迂回できる欠陥が2件塞がれた

**要点**: Anthropic が Claude Code を10日ぶりに更新し、zsh の `[[ ]]` 条件式に隠したコマンドが Bash ツールの権限チェックを迂回できた欠陥を塞いだ。「承認プロンプトを通ったものだけが実行される」という前提は、v2.1.220 以前では成立していなかったことになる。

**詳細**: 39 件の変更を含む。セキュリティ関連の修正は2件で、いずれも該当コマンドが今後は承認を求めるようになる。

- zsh が `[[ ]]` 正規表現条件の内側で隠しコマンドを実行できた Bash ツールの権限チェックバイパス
- Windows で PowerShell の権限チェックが引用符を含むパスを誤処理していた問題

サンドボックス側にも新しい防御が入った。Linux / WSL で資格情報ファイルに `mode: "mask"` を指定すると、サンドボックス内のコマンドはセンチネル値の複製（ファイル全体、または `extract` 正規表現が捕捉した範囲だけ）を読み、サンドボックスプロキシが egress 時に実物へ差し替える。macOS ではファイルマスキングは `deny` にフォールバックする。

エージェントの挙動そのものも変わった。

- バックグラウンドセッションは作業を保全するため commit と push を行い、draft PR はタスクが要求するときだけ開き、CLAUDE.md の git 指示に従い、最後に必ず作業場所を報告する
- `/fork` したセッションは元セッションのチェックアウトを共有せず、自前の worktree を作る
- VSCode に Focus view が入った（`Ctrl+Alt+F`。ツール実行のログをターンごとの折りたたみ要約の裏に隠し、実行中インジケータだけを出す）
- `claude-api` skill に `prompt-audit` サブコマンドが加わり、旧世代モデル向けに書かれたプロンプトとツール説明を検出できる

不具合修正では、thinking 無効かつ effort `xhigh` / `max` で WebSearch が 400 を返す問題と、print mode（`-p`）で `--mcp-config` の MCP サーバーが初回ターン前に接続されずモデルがツール呼び出しをそのまま文字列として出力していた問題が直った。auto mode の権限チェックは会話プレフィックスのキャッシュを判定間で再利用するようになり、プロンプトキャッシュ費用が下がる。

- https://code.claude.com/docs/en/changelog
- https://github.com/anthropics/claude-code/releases/tag/v2.1.221

### 2. GitHub Spark が退役する — 8/31 を過ぎるとコードを取り出せない

**要点**: GitHub が Spark の提供終了を告知した。8/4 で新規登録とアプリ作成が止まり、8/31 に既存ユーザーのアクセスが切れる。Spark 上のコードは「いつでも取り出せる資産」ではなくなり、8/31 までの手動エクスポートが唯一の退避手段になった。

**詳細**: 期限は2段階に分かれている。8/4 時点で新規ユーザー受け入れと新規アプリ作成が停止済み、8/31 に既存ユーザーのアクセスとエクスポートの両方が終了する。デプロイ済みアプリは 8/31 以降も動き続けるが、`llm()` を使っているアプリは推論基盤の GitHub Models が 7/30 に退役済みのため既に動作していない。`llm()` を使い続けるには別の推論プロバイダに載せ替え、自分の API キーとコストを持つ必要がある。

エクスポート手順は Spark workbench を開き、メニューから「Create repository」を選ぶ。GitHub は退役理由を「AI モデルとエージェント型開発ツールが大きく進歩し、VS Code・Copilot CLI・GitHub Copilot アプリ内の統合ワークフローのほうが適した代替になった」と説明している。

- https://github.blog/changelog/2026-08-04-upcoming-deprecation-of-github-spark-on-github-com/

### 3. Cursor のエージェントが Google Workspace に書き込めるようになった — 権限境界がリポジトリの外へ出た

**要点**: Cursor が Drive / Gmail / Calendar のプラグイン3種を出し、エージェントが読むだけでなく書けるようになった。コーディングエージェントの権限境界がリポジトリ内から業務メールと予定表まで広がり、承認範囲を決める単位が変わる。8/3 公開で、当リポジトリでは本日はじめて検出した。

**詳細**: 3プラグインの操作範囲は次のとおり。

- Google Drive: ファイルとフォルダの検索、コンテンツの閲覧とダウンロード、ファイルの作成と整理
- Gmail: メールの検索と閲覧、下書き作成と送信、ラベル適用とスレッド管理
- Google Calendar: 予定の閲覧、イベントの作成と更新、空き時間の検索

導入は Cursor Marketplace、または Cursor 内の Customize ページから行う。公開ページには対象プラン・利用上限・追加料金の記載がなく、これらは未確定。
