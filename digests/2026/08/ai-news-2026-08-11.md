### 1. OpenAI が「拒否を減らしたモデル」を審査付きで防御側に配り始めた — 3日前には自社モデルの開発を止めていた

**要点**: OpenAI が、攻撃的セキュリティ用途で意図的に拒否を減らしたモデル GPT-5.6-Cyber を、審査を通した防御側にだけ配布し始めた。exploit chain 開発は「モデルが断るもの」から「審査を通せば使えるもの」へ変わる。9/1 からは Daybreak 全アカウントでハードウェアキーが必須になる。

**詳細**: 8/10 に Daybreak を2層へ分割した。

- Daybreak Blue: GPT-5.6 Sol を含む汎用フロンティアモデルを、承認済みの防御担当者へ日常的なセキュリティ業務向けに開放する
- Daybreak Red: GPT-5.6-Cyber を、認可された脆弱性研究・exploit 検証・セキュリティテスト向けに、より厳しい審査を通した相手にだけ開放する
- 両層とも身元確認・アカウント保護・監視・法的宣誓が必須で、**9/1 からハードウェアセキュリティキーが全アカウント必須**になる

GPT-5.6-Cyber は GPT-5.6 Sol を基盤に、ゼロデイ発見と exploit chain 構築で性能を上げ、dual-use 領域の拒否を減らすよう訓練されている。社内テストでは高度なセキュリティ要求の **95%** に応答し、対象には exploit chain 開発・認証バイパス・権限昇格が含まれる。実績として Chrome の JS エンジン V8 で未知の脆弱性2件を発見し、連鎖させるとメモリ破壊と V8 heap sandbox のバイパスが可能だった。Google が協調開示を経て修正し **CVE-2026-15903** が割り当てられている。Preparedness Framework では GPT-5.6 Sol・GPT-5.6-Cyber とも cybersecurity を High と評価し、Critical 閾値には達していないとした。

3日前の 8/7 には、未公開モデル Astra について cybersecurity 能力が Critical である可能性を排除できないとして、OpenAI が開発の一部を停止している。安全要件を満たさない社内テストは即時中止し、政府機関と選定した安全性組織との追加試験を準備するとした。フロンティアラボがサイバー能力を理由に自社モデルの進行を公に減速した初の事例であり、**同じ週に「止める側」と「配る側」の両方を実行した**形になる。

### 2. Meta が 30B のエージェントモデルを Apache 2.0 で公開した — エージェント用途がローカル GPU 1枚に降りてきた

**要点**: Meta が 30B のエージェント特化モデル Muse Glimmer を Apache 2.0 で公開し、量子化すれば 24GB VRAM 1枚で動くようにした。SWE-Bench Verified 76.0%。「まともなエージェントはクラウド API 前提」という条件が、手元の1枚で足りる側へ動いた。

**詳細**: `meta-models/Muse-Glimmer-30B` は HF 上で作成日 2026-08-09・likes 578（8/11 時点）。告知は 8/10。構成は約 29.6B の dense causal transformer に約 1.8B の ViT-G/14 perception encoder を組み合わせたもので、52層・sliding-window attention（2048トークン）・コンテキスト 131,072+ を持つ。入力はテキストと画像、出力はテキストのみで、画像1枚あたりの視覚トークン上限は 4,096。

ベンチマークは SWE-Bench Verified **76.0%** / SWE-Bench Pro 51.2% / AIME 2026 94.7% / MCP Atlas 75.5%。VRAM は full precision で 64GB、K-Quant-Dynamic で 32GB、K-Quant-17GB で **24GB** に収まり、劣化は 0.2〜1.0% とされる。Muse Spark からの蒸留で、DFlash による高速化は RTX 5090 で 3.1倍・M5 Max で 1.8倍・M4 Max で 1.5倍。

公式の GGUF と ExecuTorch-PTE に加え、8/10 のうちに unsloth / mlx-community / lmstudio-community / RedHatAI / Abiray などサードパーティの量子化が出そろっており、ローカル実行の経路は当日から整っている。

- https://huggingface.co/unsloth/Muse-Glimmer-30B-GGUF

### 3. Copilot CLI v1.0.79 が安定版になり、設定キー2組が移行なしでリネームされた

**要点**: GitHub が Copilot CLI v1.0.79 を安定版として公開し、設定キーを2組リネームした。旧キーは移行なしで黙って無視されるため、`allowDevToolCaches: false` で dev ツールアクセスを絞っていた環境は、更新すると既定の on に戻る。

**詳細**: 公開は 8/10 16:19 UTC で、安定版としては 1.0.78（8/3）以来1週間ぶり。破壊的変更は2件ある。

- `allowDevToolCaches` → **`allowDevToolAccess`**: キャッシュだけでなく dev ツールの設定とレジストリまで許可する意味に拡張された。旧キーは黙って無視され、既存の `false` オプトアウトは既定（on）へ戻る。settings.json と MDM ポリシーの両方を更新する必要がある
- `sandbox.gitAuth` / `sandbox.ghAuth` → **`sandbox.auth.git` / `sandbox.auth.gh`**: 1.0.79-8 で先行していた変更が安定版に入った。後方互換はなく、旧キーは SDK リクエストで invalid として拒否される

機能面では、モデルピッカーが Recent / Recommended / New 等にグループ化され Shift+Tab で移動できるようになり、kimi-k3 が選択肢に加わった。大規模モノレポの正規表現検索が ripgrep から tgrep に替わり、`/model` は既定でセッションスコープになった（将来のセッション既定は `/config model`）。Sessions タブとサイドバーから複数セッションを同時に管理でき、`--plan` と `--mode autopilot` を併用すると承認待ちなしで計画から実装まで進む。サンドボックス側は Windows Dev Drive での実行に対応し、macOS の UNIX ドメインソケット（tsx / vite / esbuild 等）が復活、Azure DevOps / GitHub Enterprise / GitLab への HTTPS 認証つき git も通るようになった。

- https://github.com/github/copilot-cli/releases
