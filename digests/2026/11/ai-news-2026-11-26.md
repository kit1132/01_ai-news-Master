### 1. [破壊的変更+新機能] Anthropic が Claude Code `2.1.332` を出した — Foundry の既定モデルが Sonnet 5.5 に変わり、Desktop の OTel `service.name` も変わったので、クラウド経由の配備と監視フィルタは見直しが要る

**要点**: Anthropic が 11/24 に Claude Code `2.1.332` を npm `latest` にした。MCP サーバーからスキルを受け取る機能（beta）が入った一方、Microsoft Foundry の既定モデルと `sonnet` / `opus` エイリアスが 5.5 世代へ移り、Desktop の Code タブの OTel `service.name` が `claude-code-desktop` に変わった。モデル名や `claude-code` で絞る運用は、更新した時点でずれる。

**詳細**:
- 追加:
  - MCP サーバー由来のスキル（beta）: `/` メニューに `server:skill` の形で出る
  - `PreSkillShellCommand` フック: スキルやコマンドが読み込み時に走らせるシェルコマンドを拒否できる（`2.1.331` 以前でこの名前を書いた設定ファイルは起動時にダイアログが出る）
  - 起動ヘッダーに Cyber Verification Program のアクセス階層を表示する
- モデルの既定とエイリアス:
  - Microsoft Foundry: 既定モデルが Sonnet 5.5。`claude-sonnet-5-5` をデプロイするか `ANTHROPIC_DEFAULT_SONNET_MODEL` を設定する。Foundry の `opus` は Opus 5.5、Sonnet 4 / Opus 4 / 4.1 は退役扱い
  - Google Cloud Agent Platform: `sonnet` が Sonnet 5.5 になり、`VERTEX_REGION_CLAUDE_5_5_SONNET` を読む（`4_5` の変数だけだと `CLOUD_ML_REGION` か `us-east5` へ）
  - Amazon Bedrock: `sonnet` は Sonnet 4.5 のまま。Bedrock Mantle の `sonnet` が Haiku 4.5 に解決されていた不具合は Sonnet 5 に直した
  - Bedrock Mantle / Agent Platform / Foundry で Sonnet 5 / 5.5 に移ったセッションは、モード未設定なら auto mode で始まる。止めるには `disableAutoMode` を `"disable"`
  - Claude apps gateway: 組み込みモデル一覧の2番目が Sonnet 4.5 から Sonnet 5.5 に変わった
- 運用に効く変更:
  - OTel: Desktop の Code タブの既定 `service.name` が `claude-code-desktop` に変わった。旧名のままにするには `OTEL_SERVICE_NAME`
  - Self-hosted runner: `CLAUDE_CODE_OAUTH_TOKEN` の接頭辞が `oat02-` にもなる。`oat01-` で照合するプロキシ規則やログのマスクは更新が要る
  - macOS で computer use が有効なとき `computer-use` は予約スキル名になり、同名の自作スキルは読み込まれない
- npm の `stable` は `2.1.325` から `2.1.326` に進んだ

### 2. [新機能] Anthropic が artifact を Mac / Windows のデスクトップアプリとして入れられるようにした — Team は既定オンなので、管理者が何もしなければ社員が作ったアプリが端末に入る

**要点**: Anthropic が 11/24、Claude の artifact を Claude for Mac / Windows から独立したアプリとして入れる機能を全プランで beta にした。Team は既定オン（全面的なコンピューターアクセスはオフ）、Enterprise はオーナーが有効にするまでオフ。社内で作った小物ツールが、ブラウザーの外で端末の権限を持てるようになった。

**詳細**:
- 権限は3段: 既定（ブラウザーでできることだけ）／アプリ権限（最前面ウィンドウ・グローバルショートカット・通知）／全面的なコンピューターアクセス（毎回確認せずにプログラムを実行し、ファイルを読み書き・削除する）
- 全面アクセスは自作のアプリか、Team / Enterprise では組織内で作られたアプリに限る。権限は現行版にだけ掛かり、更新（自分の編集を含む）のたびに再確認される
- Anthropic はインストール前にアプリを審査しない。アプリが外部サイトから読み込む部分は確認なしに変わりうる
- 対象外: HIPAA 対応組織とハイブリッド配備。Claude Docs / Slides / Sheets の artifact は入れられない。開くにはオンラインでサインインが必要で、アプリから Claude への要求はプランの利用上限に数えられる
- 同日の release notes には、接続アプリへファイルを送り、接続アプリからファイルを保存する機能（beta）もある。Pro / Max / Ultra へ順次、Team / Enterprise はオーナーが有効化

出典:
- https://claude.com/resources/articles/install-as-app
- https://support.claude.com/en/articles/12138966-release-notes

### 3. [破壊的変更] GitHub が Copilot CLI 安定版 `v1.0.116` を出した — 計画の承認画面から fleet が消え、実験的拡張の「Load Only」は無効に移されるので、拡張を前提にした環境は再設定が要る

**要点**: GitHub が 11/25 に Copilot CLI `v1.0.116` を安定版にした。計画承認で fleet を選べなくなり（`/fleet` は残る）、実験的拡張の設定が Enabled / Disabled の2値になって既存の「Load Only」は無効へ移行する。サンドボックスに止められたコマンドは手元に戻されず、Copilot が止まるようになった。

**詳細**:
- 挙動の変更:
  - サンドボックスがコマンドを止めたとき、Copilot は実行を利用者に戻さずに止まり、ポリシーが許せばセッション単位でサンドボックスを外すよう提案する
  - ACP クライアントのシェル承認は、説明文ではなく実行するコマンドそのものを表示する
  - `-i` で渡したプロンプト・リポジトリの起動プロンプト・復元したスケジュールは、信頼で起動した MCP サーバーを最大30秒待つ
  - `/restart` は `/agent` で選んだエージェントを保つ。組織管理の MCP サーバー（Connectors を除く）は個別の遅延・サインイン警告を出さず、起動時の要約にまとめる
- 追加: Copilot が起動する全プロセスに環境変数を渡す `env` 設定、プラグインと単体の MCP サーバーが同じエンドポイントにつながったときの警告、ACP エディターでのコンテキスト長の選択
- pre-release は `v1.0.116-5`（11/25）まで刻まれた

出典:
- https://github.com/github/copilot-cli/releases
