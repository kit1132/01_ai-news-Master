## 今日のハイライト

### 1. [新機能] GitHub が Copilot CLI `v1.0.117` で、TLS を中継するプロキシの下でも sandbox 内のコマンドが社内 CA を信頼できる設定を足した — 管理設定で配れるので、企業プロキシ環境で sandbox が通信に失敗する前提が変わる

**要点**: GitHub が 11/27 に Copilot CLI の安定版 `v1.0.117` を出した。`sandbox.userPolicy.network.extraCaCertificates` をユーザー設定か管理設定に書くと、sandbox 内のコマンドが追加の CA 証明書を信頼する。社内プロキシが TLS を中継する組織でも、sandbox を切らずに使えるようになる。

**詳細**:
- 前の安定版は `v1.0.116`（11/25）。pre-release `v1.0.117-0`〜`-5` の内容をまとめた版で、リリース本文に「破壊的変更」の表記は無い
- 権限: MCP サーバーの名前が組み込みの権限種別と同じでも、そのツールを承認したときに組み込みの要求まで承認されなくなった。autopilot で始めると、拡張を起動する前に1件ずつ確認する（従来は承認者がいないとして全て拒否していた）
- sandbox: 書き込める git worktree の中でも、リポジトリの設定ファイルは sandbox のコマンドとエージェントの編集から読み取り専用になる。リンクした worktree での commit・branch 作成・stash が再び動く
- カスタムエージェント: ツールを明示して公開する仕組みが入り、カスタムエージェントが使うツールを選んで有効にできる。サブエージェントは、プロンプトが無いエージェントファイルでもツール一覧に従う
- モデル: リポジトリが使えない提供元のモデルを固定しているとき、黙って提供元を切り替えずにエラーを出す。`/model` の選択画面にサービスの告知と退役予定のモデルの印が出る
- Assisted Permissions: plan mode ではブランチ作成とパッケージのインストールの前に確認する

出典:
- https://github.com/github/copilot-cli/releases/tag/v1.0.117

### 2. [破壊的変更+新機能] Stably AI が Orca `v1.4.280` で、使用量の表示・bot のアバター作成・コミットメッセージの生成に Antigravity の `agy` を使うのをやめた — `agy` は CLI と Orca のチャットからだけ使う前提に変わった

**要点**: Stably AI が 11/27 に Orca `v1.4.279` と `v1.4.280` を出した。`v1.4.280` は使用量メーターの残量確認、bot のアバター生成、コミットメッセージなどソース管理の文面の作成に `agy` を使わなくした。前日の Gemini CLI 削除に続き、Google 系エージェントの使い道を Orca が絞っている。

**詳細**:
- `v1.4.280`（11/27・Latest）:
  - Bot: グループのルームとスレッドをタブから名前変更できる。使用上限で止まった bot に琥珀色のゲージが付く。Slack では依頼を受けたスレッドか DM に結果を返す
  - チャット: エージェントの質問が入力欄の上に出る。Antigravity のチャットは最初のメッセージ前から `/` でコマンドとスキルが出て、上限で止まるとリセット時刻を示し、その後に再開できる
  - WSL: Codex のモデルとプラグインの変更が Linux ディストリビューション側に保存される。プロジェクトを WSL へ移すと、移るワークスペース・ペイン・チャットの数を出す
  - 予告: サイドバーと PR レビューの作り直し、アカウントの自動切り替え、入力欄でのエージェントハーネスの切り替え
- `v1.4.279`（11/27）: Git レビューの配置替え、ブラウザ注釈パレットの移動。設定を読み直したときに Codex / Cursor / Copilot / Kiro の既存フックを認識し、Droid のカスタムフックを残す

出典:
- https://github.com/stablyai/orca/releases
