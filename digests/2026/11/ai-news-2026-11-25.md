### 1. [料金+新機能] Anthropic が Claude Ship を出した — PR のレビュー・修正・承認までを Claude に任せられるようになり、Code Review は単体機能から PR 運用の一部になった

**要点**: Anthropic が 11/23、Team / Enterprise の GitHub リポジトリ向けに Claude Ship を出した。Code Review（GA）に、CI 失敗やコンフリクトを直す PR Steward と、リポジトリ内のポリシーファイルで定型の変更を自動承認する Claude Approvals（どちらも beta）が加わり、レビューは「指摘を書く」から「承認まで進める」に広がった。

**詳細**:
- Code Review: レビューの深さを Quick / Standard / Deep からリポジトリごとに選ぶ
- PR Steward: push のたびに変更内容と戻し方をコメントする。`@claude` で指示、`@claude stop` で停止。承認とマージはしない
- Claude Approvals: 既定ブランチのポリシーファイルで動き出す。Code Review の指摘や自然言語の分類器を判断材料にする。まず観察モードで始め、そのあと branch protection で必須にする手順を推奨している
- Claude Code / デスクトップアプリ: `/ship` で push・PR 作成・レビュー・修正を自分で回せる（11/23 から順次）
- 料金: トークン課金。Code Review と PR Steward は管理者が支出上限を設定できる。Approvals に基本料は無いが、分類器とポリシーが呼ぶ Code Review は観察モードでも課金される
- 対象外: ZDR・HIPAA 構成・顧客管理の暗号鍵（CMEK）を使う組織
- 特典: 対象の Enterprise 組織は **$10,000** 以上のクレジットを 2027-01-15 まで請求でき、請求から30日以内に使う
- 実績: Claude Code チームでは 6〜9月にマージ済み PR が2倍超、revert の割合が40%超減った

出典:
- https://claude.com/resources/articles/introducing-claude-ship

### 2. [破壊的変更+料金] Google が Workspace の MCP サーバーと CLI を GA にした — 外部の AI エージェントは 2027-02-01 から REST API を直接呼べなくなり、標準枠を超える利用は 4/1 から課金される

**要点**: Google が 11/24、Gmail・Drive・Docs など8サービスの Google ホスト MCP サーバーと Workspace CLI を全顧客に GA した。あわせて外部 AI エージェントは REST API ではなく MCP を使うことが求められ、2027-02-01 に技術的な強制が始まる。Workspace API を叩く自作エージェントは、2か月余りで経路の作り直しが要る。

**詳細**:
- MCP サーバー: Gmail / Drive / Docs / Sheets / Slides / Calendar / Chat / Tasks（Keep は近日）。Rapid / Scheduled Release とも2週間以内に展開
- 利用枠: Standard（無料・公開レート上限。現行開発者の99%超が該当）と Scaled（高い上限）の2段。Scaled は 2027-04-01 から日次無料枠を超えた分だけ課金（Gmail / Calendar / Drive / MCP サーバーから）
- 既存プロジェクト: Standard の上限を超えるプロジェクトは「組織内専用」に指定するか Scaled に切り替えないと、4/1 以降 Standard の上限に戻される
- 管理者: Admin console の Security > API Controls で外部 AI ツール・MCP・CLI・API のアクセス管理、機微な操作への人の確認ルール、エージェントの監査ログを扱える。既存のユーザー単位の DLP がエージェントにも掛かる
- 識別: 外部 AI エージェントは OAuth で自分を名乗る必要があり、OAuth クライアントに `is_agentic` を付けられる。新しい Workspace AI Tools Addendum は API 由来データの長期保存とスクレイピングを禁じる

### 3. [破壊的変更+新機能] GitHub が Copilot CLI 安定版 `v1.0.115` を出した — 空の `--available-tools=` が「全ツール」から「ツールなし」に反転し、スクリプトの前提が逆になった

**要点**: GitHub が 11/24 に Copilot CLI `v1.0.115` を安定版にした。`--available-tools=`（空指定）の意味が全ツールからツールなしへ反転したほか、Windows のサンドボックスでパッケージ照会が既定オンになり、拒否パスの glob が100件超に当たるとコマンドが起動しなくなった。CLI を自動化で呼ぶ設定は挙動が変わる。

**詳細**:
- 挙動の変更:
  - `--available-tools=` / `--available-tools ''`: モデルにツールを渡さない（以前は全ツール）
  - `--max-ai-credits` と `--resume` / `--continue` の併用: 再開したセッションの上限として効く（以前は無視）
  - フックの許可確認で Esc: ターンを止める（以前はエージェントが続行）
  - Windows サンドボックス: パッケージ照会が既定オン。止めるには `sandbox.userPolicy.capabilities` を `[]` にする
  - 拒否パスの glob が100件を超えて一致すると、サンドボックス内のコマンドが起動に失敗する（エラーに glob 名が出る）
- 追加: `/model` でカスタムプロバイダーのモデルを追加・管理できる（`Ctrl+X` → `A`）。Gemini 4 Hydrogen・GPT-6.2 Astra・MAI-Code-2-Flash を picker に追加。`showTimelineTimestamps` 設定、ACP エディター向けの構造化された確認質問
- pre-release は `v1.0.116-0`（11/24）に進んだ

出典:
- https://github.com/github/copilot-cli/releases
