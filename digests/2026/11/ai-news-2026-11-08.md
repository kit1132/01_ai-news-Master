### 1. [破壊的変更+新機能] GitHub が Copilot CLI `v1.0.107` を出し、`alwaysApply: false` のプラグインルールを既定で読み込まなくなった — 全セッションに効いていたルールが、`/instructions` で有効にするまで効かなくなる

**要点**: GitHub が 11/6、前日の `v1.0.106` に続けて Copilot CLI の安定版 `v1.0.107` を出した。これまで `alwaysApply: false` のプラグインルールは、`/instructions` か `/plugins` を開くまで全セッションに掛かっていた。更新後は `/instructions` で有効にするまで掛からない。ルールが効いている前提の運用は、更新後に挙動が変わる。

**詳細**:
- 既定の変更: `/statusline` の `quota` 項目は既定でオフ（`ai-used` はオン）。macOS では `copyOnSelect` が既定でオン
- 安全側の修正: `/session delete --yes=false` や打ち間違えた `--yes=<値>` で現在のセッションが消えなくなった。`copilot login --device-code` は `http://` のホストを拒否する。プラグインが有効な間はローカル marketplace を削除できない（`--force` で一緒に外す）
- 新機能:
  - `/code`: 現在のセッションを VS Code で開く
  - `/settings`: プラグイン・MCP サーバーなどを1画面で管理する統合ダッシュボードを全ユーザーに開放し、設定とローカル資源を横断検索できる
  - モデル: アカウントで使えれば GPT-6.1 Terra を選べる。`copilot config` に Fusion tier の設定が加わった
  - サンドボックス: 拡張のプロセスをサンドボックス内で動かす設定が加わった。`COPILOT_SESSION_CWD` で LSP とローカル MCP の設定を展開できる
- 挙動の修正: レビューや分析だけを頼んだのに Autopilot が自分の推奨を実装し始める問題を直した。`--resume <id>` はタスクサービスが応答しないとき10秒で諦める
- pre-release は `v1.0.108-1`（11/7）まで進んだ。`v1.0.108-0` は `-p --output-format json` の出力にセッション開始・再開・モデル変更のイベントを加える（安定版には未反映）

### 2. [新機能] GitHub が Copilot code review の設定を REST / GraphQL API で管理できるようにした — enterprise から repository まで、レビューの有効化と effort をコードで揃えられる

**要点**: GitHub が 11/6、Copilot code review の設定を API で読み書きできるようにした。これまで画面で1組織ずつ設定していた有効化・既定の effort・runner を、enterprise・organization・repository の各階層でスクリプトから管理できる。上位が管理する設定は下位で上書きできない。

**詳細**:
- 権限ごとの範囲:
  - enterprise 管理者: 全 organization の有効・無効、または判断を organization 管理者に任せる
  - organization 管理者: 有効化・既定の review effort・runner 構成
  - repository 管理者: review effort、カスタム指示と MCP ツールを使うか
- ⚠️ 認証の制約: enterprise と organization の設定エンドポイント（runner を含む）は GitHub Apps と fine-grained PAT に対応しない。repository の設定は両方に対応し、読みに Administration: read、書きに Administration: write が要る
- 出力の識別: レビューとコメントに Copilot の帰属フィールドが付き、使った effort、コメントの根拠になった skill・MCP サーバー・カスタム指示を取れる
- そのほか: レビューの agent セッションに消費した AI credits を出す。自動レビューのリポジトリルールが bypass list に対応した。Balanced effort は3つのレビューモデルの指摘を別のモデルがまとめる。失敗・タイムアウトしたレビューは1回自動で再試行する
- 対象: Copilot Pro / Pro+ / Max / Business / Enterprise

出典:
- https://github.blog/changelog/2026-11-06-copilot-code-review-api-management-and-review-overview-updates

### 3. [新機能] Cursor がエージェントとリアルタイムの音声通話で話せる「Voice Chat」を出した — 音声は Grok Voice で動き、Privacy Mode ではデータを保持しない

**要点**: Cursor が 11/6、エージェントと声で会話しながら作業を任せられる Voice Chat を出した。音声エージェントが話を聞いて、コーディングはチャットのエージェントに渡す。作業中も差分や進捗を声で尋ねられる。音声の処理は xAI の Grok Voice が担い、Privacy Mode をオンにするとゼロデータ保持で動く。

**詳細**:
- 使える場所: Agents Window・IDE・Web・Cursor for iOS。エージェントが待機中で入力欄が空のとき、送信ボタンの位置に出る波形ボタンで通話を始める
- iOS: 「Hey Siri, call Cursor」で新しいエージェントと通話を始め、ロック画面の Live Activity でミュート・終了できる
- 通話中にできること: 差分の中身を聞く、実行の状況を確かめる、そのエージェントとの過去のメッセージと通話を検索する、Project 内のワーカーを切り替える。コーディング側のエージェントも短い進捗と完了時の要約を声で返す
- 既存機能との関係: 音声入力（旧称 Voice Mode、IDE では Cmd+Shift+Space）は別機能として残る

出典:
- https://cursor.com/changelog/voice-chat
