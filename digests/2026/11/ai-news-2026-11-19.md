### 1. [破壊的変更+セキュリティ] Claude Code 2.1.327 は auto mode の課金分類器フォールバックを次の版で外すと予告し、権限確認を一段厳しくした — 「判定できなければ有料の分類器で通す」前提が、「確認か拒否に落ちる」に変わる

**要点**: Anthropic が Claude Code `2.1.327` を出し、npm の `latest` / `next` にした。auto mode の通知に、課金される分類器へのフォールバックを次の版で外すと書き加えた。外れると、その確認対象の操作は承認待ちか拒否になる。作業ディレクトリ外の読み取りやシンボリックリンクの扱いも厳しくなり、これまで通っていた Bash が確認を求めるようになる。

**詳細**:
- 権限まわりの変更:
  - auto mode: `Bash(pnpm dlx *)` のように任意のパッケージを走らせる allow ルールと、`/usr/bin/npm run:*` などパスや版を付けた形を無視し、安全性チェックに判定を任せる
  - `permissions.blockReadsOutsideWorkingDirectories`: bypass / auto mode で確認する Bash コマンドが増え、Read / Edit の deny ルール配下のパスを指すコマンドは確認ではなく拒否になる
  - 作業ディレクトリの内側とみなす範囲が変わり、一部のパスで確認が出る。一部のシンボリックリンクはパス検査で拒否する
  - `ExitWorktree`: 保存していない作業がありそうな worktree を消す前に確認する。答える人がいなければ拒否する
- セキュリティ上の注意: 最初の Bash コマンドを速くするため、承認前にシェルの起動ファイルが走るようになった（拒否しても走る）。止めるには `CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1` を設定する
- 管理設定・組織向け:
  - `attributionProject`: `admin.billing_group_tag` を設定した Claude apps ゲートウェイで、セッションの請求グループに名前を付ける
  - `x-claude-code-managed-settings-checksum`: ゲートウェイのヒントヘッダーに管理設定のチェックサムを加える（`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` の環境）
  - `claude mcp add-json <name> -`: サーバーの JSON を標準入力から読み、トークンをコマンドラインに出さずに済む
- 修正: Remote Control の worktree モードで、サーバー停止時に `.env` など git 管理外のファイルを消していた不具合を直した。全体は173項目（[VSCode] の10項目を含む）
- npm: `{stable: 2.1.311, latest: 2.1.327, next: 2.1.327}`。stable は動いていない

出典:

- https://registry.npmjs.org/@anthropic-ai/claude-code
