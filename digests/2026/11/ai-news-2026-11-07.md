### 1. [破壊的変更+新機能] Claude Code 2.1.319 で、LLM ゲートウェイ経由の auto mode が組み込み分類器へ戻らなくなった — サーバー側チェックが届かない環境では、確認または拒否になる

**要点**: Anthropic が 11/6 に Claude Code `2.1.319` を出した。テレメトリや feature flag を切った環境と LLM ゲートウェイ経由の環境では、auto mode がサーバー側の安全チェックを使えないとき、組み込み分類器に頼らず確認または拒否に回すようになった。これまで素通りしていた操作が、更新後は止まることがある。

**詳細**:
- auto mode の既定: 旧挙動に戻すには `CLAUDE_CODE_AUTO_MODE_SERVER=0` を設定する。Bedrock / Vertex / Foundry は変わらない。`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` を managed settings で設定している組織は、`CLAUDE_CODE_AUTO_MODE_SERVER=1` も managed settings に書く必要がある
- 終了コード: auto mode で安全チェックが無く操作が拒否されたとき、`claude -p` は 0 ではなく 1 で終わるようになった（テキスト出力・JSON 出力とも）
- 新しい設定:
  - `permissions.denyInsteadOfPrompting`: 権限の確認で止まるはずのツール呼び出しを拒否し、ターンを続ける（ターミナル・サブエージェント・teammate）
  - `CLAUDE_CODE_DISABLE_FEATURE_FLAGS`: テレメトリを止めずに feature flag の取得だけを止める
  - MCP tasks: MCP サーバーがツール呼び出しを task として動かすと、すぐバックグラウンドへ移す。止めるのは `CLAUDE_CODE_DISABLE_MCP_TASKS=1`
- そのほかの挙動変更: 自分でペースを決める `/loop` は、次を予約せずにターンが終わればループを終える（旧挙動は `CLAUDE_CODE_LOOP_KEEPALIVE=1`）。Claude in Chrome の組み込みツールから `shortcuts_list` / `shortcuts_execute` を削除した
- セキュリティ修正: worktree 作成時のサンドボックス脱出、細工した環境変数の接頭辞で権限チェックを逃れる Bash の抜け道、accept-edits / auto mode で `sed` が権限チェックを飛ばすケースを直した
- Claude apps gateway: `desktopHome` を持たないまま `coworkTabEnabled: false` や `chatSessionRetentionDays` に頼るポリシーに、起動時の警告を出す。Claude Desktop の **11/10 の変更**に備えたもの（変更の中身は一次で未確認）
- npm: `{stable: 2.1.311, latest: 2.1.319, next: 2.1.319}`

出典:
- https://code.claude.com/docs/en/changelog
- https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md

### 3. [新機能] Cursor がクラウドエージェントでアプリを作り、URL で社内に共有できる「Live Apps」を出した — DB・認証・ホスティングまで Cursor の中で完結する

**要点**: Cursor が 11/5、クラウドエージェントに Web アプリの作成・公開を任せられる機能を全有料プランで出した。データベース、Cursor SSO での認証、ホスティングまで用意し、公開前にセキュリティ検査を通す。社内ツールを localhost の外へ出すのに、別のホスティングを用意しなくてよくなった。

**詳細**:
- 作り方: クラウドエージェントに、アプリを作りたいと明示して指示する。必要なら Postgres を立て、データウェアハウスなどへの接続に要るシークレットを聞いてくる。公開時に一意のドメインを選ぶ
- 統制: 公開前に、決定的な検査とエージェントによる検査で、ファイルに書かれたシークレットや露出した認証情報を探す。検査を通って明示的に公開するまで公開されない。チーム管理者は全アプリと全シークレットを見られ、独自のルールを足し、止められた公開の承認や公開取り消しができる
- 共有: 特定の人・グループ・チーム全体へ、Cursor のサインインを要する形で共有する。個人プランでは一般公開もできる。スクリプトや Grok Bot から使う Cursor API キーも発行できる
- 対象: クラウドエージェントが有効な全有料プラン。デプロイ元は Cursor Origin と GitHub のリポジトリで、GitLab などは今後対応

出典:
- https://cursor.com/changelog/build-live-apps

## GitHub Copilot / Microsoft

- [破壊的変更] GitHub が 11/6、Copilot CLI の安定版 `v1.0.106` を出した（10/28 の `v1.0.105` 以来）。フラグの削除は無いが、既定値の変更が多い
  - 既定: 非対話の `-p` 実行はメモリを切った状態で始まる（`--enable-memory` で有効）。CI 環境では `autoUpdate` が既定でオフになった。パスアクセスの確認で Enter を押すと、その1回だけ許可する
  - オプション: `--excluded-tools` は `--available-tools` と併用しても効く。`--yolo` / `--allow-all` は `--resume` / `--continue` で再開したセッションにも掛かる。`/session delete` は未知のオプションをエラーにする（以前は確認なしで現在のセッションを消すことがあった）
  - JSON 出力: `-p --output-format json` などが C1 制御文字と DEL をエスケープする（パース後の値は同じ）。compaction / truncation のイベントが加わり、中断された実行は非ゼロで終わる
  - モデル: 廃止済みのモデルを一覧とピッカーから消した。Entra サインインは Windows / macOS で既定で OneAuth を使う
  - https://github.com/github/copilot-cli/releases/tag/v1.0.106
- [新機能] GitHub が 11/5、Copilot usage metrics API に2種類のフィールドを加え、管理者が Copilot code review の効果とテレメトリの欠落を数えられるようにした
  - code review: リポジトリ別の日次行に `copilot_code_review` を加えた。指摘のうち開発者が対応した件数（`total_comments_addressed` / `total_comments_evaluated`）を、重大度・review tier・指摘の種類・カスタマイズ別に出す。Copilot のレビュー後に人が変更を求めずにマージされた PR の数も出る
  - テレメトリ: ユーザー別の `client_telemetry_present` と、IDE・拡張が最低版を満たすかを示す `usage_metrics_requirements` を加えた。日次の影響人数も出る。テレメトリが届かないユーザーも利用者には数えられるが、コード行数・機能別・モデル別の内訳が欠ける
  - https://github.blog/changelog/2026-11-05-usage-metrics-api-adds-code-review-details-and-addressed-rate
  - https://github.blog/changelog/2026-11-05-usage-metrics-api-flags-telemetry-and-version-gaps
