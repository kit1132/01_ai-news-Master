## 今日のハイライト

### 1. [破壊的変更+新機能] Claude Code 2.1.317 — セッション内の `claude -p` が別セッション扱いになり、gateway に費用レポート API が付いた

**要点**: Anthropic が Claude Code `2.1.317` を 11/3 に出した。セッションの中で動かす `claude -p` は、もう親セッションの ID と transcript を共有しない。self-hosted runner で旧挙動に頼っていた場合は環境変数で戻す必要がある。管理者は Claude apps gateway から期間・開発者・IdP グループ単位で過去の費用を API で読めるようになった。

**詳細**:
- 旧挙動に戻す方法: `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1`。設定すると、セッション内の `claude -p` が以前の版と同じくそのセッションの ID と transcript を使う
- 費用レポート: `GET /v1/organizations/analytics/cost`。期間を指定し、合計・開発者別・日別・IdP グループ別で集計できる。`admin:` を設定した gateway は開発者ごとの IdP グループを毎日記録し、`admin.identity_retention_days` の期間だけ保持する
- 組織向け: Desktop の Code タブで、組織のリモート管理設定がまだ読み込まれていないときと、読み込まれたときに通知が出る。OTel の metrics / events / spans に `anthropic.plan`・`anthropic.seat_type`・`anthropic.provider`・`anthropic.custom_base_url` が加わった
- 安全側の追加: web / shell ツールがアカウントのメールアドレスをネットワークへ送る前に確認を求める。Agent SDK の hook callback に `onFailure: "block"` が加わり、失敗した callback が操作を止められる
- 挙動の変更: Read ツールの「前回の Read から変更なし」スタブが廃止され、同じファイルをもう一度読むと内容が返る。メインと違うモデルで動く subagent / teammate は、セッションの effort ではなくそのモデルに保存した effort（無ければ既定値）を使う
- npm は `{stable: 2.1.311, latest: 2.1.317, next: 2.1.317}`。stable は 2.1.309 から上がった

出典:
- https://code.claude.com/docs/en/changelog
- https://registry.npmjs.org/@anthropic-ai/claude-code

### 2. [新機能] GitHub Copilot が JetBrains Air で使えるようになった — JetBrains AI のクレジットではなく Copilot の契約でクラウドタスクを回せる

**要点**: GitHub が 11/3、JetBrains のエージェント環境 Air のエージェント選択に Copilot を加えた。接続は Agent Client Protocol（ACP）で、IDE 内のローカルタスクと Air Teams 経由のクラウドタスクの両方を動かせる。JetBrains で Copilot を使う経路が、従来のプラグインに加えて Air の2つになった。

**詳細**:
- クラウドタスクは新しい VM 上の Docker コンテナで動き、通信はすべてプロキシを通る。タスク間で状態は引き継がない
- 前提: Air Teams を有効にした JetBrains の組織アカウント、Copilot の契約、Air 管理者による Copilot の有効化
- ⚠️ 個々のタスクが個人の Copilot プランと組織のプランのどちらで課金されるかは選べない。Air のガバナンス・分析機能に Copilot の利用は含まれない
- Air への接続時に Copilot の権限は要求されない。契約やクレジットはクラウド環境の起動時に確かめ、足りなければタスクが失敗する

出典:
- https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air
