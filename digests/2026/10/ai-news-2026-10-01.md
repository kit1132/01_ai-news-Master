### 2. [新機能] Anthropic が Claude Code 2.1.285 で接続先 API プロバイダを管理者が制限できる `allowedProviders` を加えた — 社内端末で Bedrock / Vertex / 独自エンドポイントのどれを使わせるかを設定で縛れるようになった

**要点**: Anthropic が Claude Code `2.1.285`（9/29 publish）の changelog を公開した。管理設定 `allowedProviders` で、端末が使える API プロバイダを Anthropic API・Bedrock・Vertex AI・Foundry などから選んで限定できる。WebFetch を環境変数で無効にする手段も加わった。

**詳細**:

- 追加（抜粋）:
  - `allowedProviders`: Anthropic API / カスタムエンドポイント / Bedrock / Mantle / Vertex AI / Foundry / Claude Platform on AWS / Cloud gateway から許可するものを指定する managed setting
  - `CLAUDE_CODE_DISABLE_WEB_FETCH`: WebFetch ツールを無効にする
  - `claude --desktop`: カレントディレクトリか、`--continue` / `--resume <id>` のセッションを Claude デスクトップアプリで開く
  - `claude plugin configure <plugin>` と `claude plugin install --config <server>.<key>=<value>`: 同梱 `.mcpb` MCP サーバーの設定をインストール時に渡せる
- 修正（抜粋・全約130項目）:
  - OS が managed settings ファイルの読み取りを拒否すると起動しなかった問題。警告して、そのファイルのポリシーなしで起動するようになった。それ以外の読み取りエラーと解析不能なファイルは従来どおり起動を止める
  - `ANTHROPIC_AUTH_TOKEN` で Anthropic API に認証するセッションが組織ポリシーを読み込んでいなかった問題
  - PowerShell ツールのコマンド解析器が起動失敗したとき、deny / ask ルールの確認を飛ばしていた問題
  - fork サブエージェントが親の plan mode / `dontAsk` を引き継がなかった問題
- npm の dist-tags は `{stable: 2.1.280, latest: 2.1.286, next: 2.1.286}`。`2.1.286`（9/30 17:14 UTC publish）は changelog に未掲載で、中身は分からない。`stable` は `2.1.277` から前進した

**詳細**:

- 日程（一次）:
  - 10/5: Workspace で skills の展開開始（11月中旬に完了予定）
  - 10/13: Gemini アプリで skills の展開開始（11月中旬に完了予定）

  - 2027-03-01 以降（Business / Enterprise）: Gems の作成・編集・利用が不可になり、残った Gems は下書きの skill に自動移行する。「Ask a Gem」ステップを含む Workspace Studio フローは動かなくなる
  - 2027-06-01 以降（Education）: 同様。Classroom と Gemini LTI 対応 LMS からも消える
- すでに「Ask a Gem」ステップを含む Workspace Studio フローは新規作成できない（既存は動く）
- skills は1つのプロンプトで複数を重ねて使える。Gemini アプリと Workspace の間では同期しないので、両方で使うなら別々に作る
