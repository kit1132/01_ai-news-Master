### 1. [新機能] GitHub が Copilot の assisted permissions を CLI・Copilot アプリ・VS Code で GA にした — コマンド実行の許可を毎回人が押す前提が、LLM が安全と判定したものは自動で通る前提に変わる

**要点**: GitHub が 10/26 に、Copilot がコマンド実行・パス参照・URL を開く許可を求めたとき LLM が判定し、明らかに安全なものだけ自動で通す assisted permissions を GA にした。Enterprise 管理者は Allow All を禁じたまま Assisted を許可でき、新規セッションの既定モードも決められる。

**詳細**:

- 有効化
  - Copilot CLI: `/permissions` → assisted
  - Copilot アプリ: モードピッカー → Tool permissions → Assisted
  - VS Code: 権限ピッカー → Assisted permissions
- Enterprise 管理設定: Allow All だけを禁止して Assisted を残す、Assisted だけを無効にする、新規セッションの既定モードを指定する、の3通りができる。既定のモードがポリシーで使えないときは手動承認で始まる
- Copilot CLI `v1.0.104`（10/27 Latest）で、Assisted Permissions は experimental モードなしで使えるようになった。同じ版で、管理モデル「fusion」はセッションを Auto で始めて `fusionTier` 設定を適用し、Autopilot の対話・SDK セッションは添付したバックグラウンドタスクを `COPILOT_TASK_WAIT_TIMEOUT_SECONDS` で打ち切らずに待つ（`-p --autopilot` は従来どおり打ち切る）

- https://github.blog/changelog/2026-10-26-github-copilot-assisted-permissions-generally-available
- https://github.com/github/copilot-cli/releases

### 2. [新機能+仕様] Anthropic が Claude Code `2.1.311` で、Bedrock / Vertex / Foundry 利用時のモデル設定を `downloads.claude.ai` の署名ファイルから読むようにした — クラウド経由の閉じた環境でも Anthropic のホストへの通信が1本増える

**要点**: Claude Code `2.1.311`（npm 10/26 publish）が、Bedrock・Mantle・Vertex・Foundry でもモデル設定を `downloads.claude.ai` から取得するようになった。止めるには `CLAUDE_CODE_MODEL_CATALOG=off` が要る。同じ版で設定ファイルの `DISABLE_COMPACT` は圧縮をオフにする方向にしか効かなくなった。

**詳細**:

- 組織の設定に関わる変更
  - `CLAUDE_CODE_MODEL_CATALOG=off`: Bedrock / Mantle / Vertex / Foundry で署名つきモデル設定ファイルの取得を止める
  - `DISABLE_COMPACT`: 設定ファイルと mod の `$.env.set` からは圧縮をオフにできるだけで、オンに戻せない
  - VS Code 拡張: VS Code のテレメトリー設定がオフのとき、セッションを `DISABLE_TELEMETRY` つきで起動し、利用メトリクス・エラー報告・feature flag の取得をしない
  - `ultrathink`: 対話ターミナルで Anthropic API 経由の Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 のターンを xhigh effort で動かす
- 修正: 標準コンテキストのセッションが 200K トークンを超えたとき「Usage credits required for 1M context」で止まっていた不具合を直し、会話を圧縮して続けるようにした。API が再試行不可とした要求を再試行し続け、`CLAUDE_CODE_RETRY_WATCHDOG` では無期限に止まることがあった不具合も直した
- `[1m]` 接尾辞は効果のないモデルの名前と ID から外した（指定は引き続き受け付ける）
- `self-hosted-runner` に `--hold-idle-file` / `--max-hold-min` を追加した。Claude Tag の管理分析に Skills ビュー（Slack チャンネルでの各スキルの実行回数と未使用スキル）が加わった
- npm は `{stable: 2.1.308, latest: 2.1.311, next: 2.1.312}`。`2.1.312`（10/27 publish）は changelog に未掲載

- https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md
- https://registry.npmjs.org/@anthropic-ai/claude-code

### 3. [破壊的変更+新機能] Stably AI が Orca `v1.4.242` で、使う Claude フォルダの `keybindings.json` に自前のショートカットを1つ書き込むようにした — Orca から起動した Claude Code の設定ファイルを Orca が編集する前提に変わる

**要点**: Orca `v1.4.242`（10/27 Latest）が、Orca のペインにだけ自前のプラグインを読み込み、使う Claude フォルダごとに `keybindings.json` へショートカットを1つ足すようにした。Settings → Agents でオフにでき、起動中の Claude セッションは再起動が要る。Codex の Ask モードは読み取り専用になった。

**詳細**:

- Claude 連携: サイドバーやダッシュボードでサブエージェントを押すと同じターミナルでその記録を表示し、親を押すと戻る（Claude の status hook が有効なら既定でオン）。再開した Claude セッションは effort と起動フラグを保つ。アカウント切替時に、旧アカウントでサインインしたままの System default フォルダのセッションを再起動するよう促せる
- Codex: Ask モードは読み取り専用で動き、ワークスペースを編集する前に確認する（Approve for me / Full access は変わらない）。再開した Codex は直前に与えた権限を保つ
- 互換性: ペアリングしたサーバーのチャットは、サーバーを更新するまで旧 Ask の挙動のまま。ペインを新しいタブへ移す操作と、リモートの Claude ターミナルを Chat で続ける操作はサーバー側にも `v1.4.242` が要る。WSL 接続は bash 経由になり、bash が無いか古いと Node に戻る

- https://github.com/stablyai/orca/releases
