## 今日のハイライト

### 1. [破壊的変更+新機能] Anthropic が Claude Code `2.1.299` / `2.1.300` を1日で2版出し、MCP の許可ルールとフックの入力検証を厳しくした — `mcp__a` のような前方一致の許可で別サーバーまで通っていた設定は効かなくなる

**要点**: Claude Code の MCP 許可ルールは、名前の一部ではなくサーバー名全体で一致させる形に変わった。フックが返す `updatedInput` も Claude 自身の入力と同じく検証され、不正な値はツール呼び出しの拒否になる。設定次第では、更新しただけで許可されていた操作が止まる。

**詳細**:

- 版と公開時刻（npm）: `2.1.299` は 10/14 00:23 UTC、`2.1.300` は 10/14 14:27 UTC に出た。dist-tags は `{stable: 2.1.292, latest: 2.1.300, next: 2.1.300}`
- 既存の設定に効く変更（2.1.299）
  - MCP 許可ルール: `mcp__a` は `a__b` や `a_` という名前のサーバーを許可しなくなった。`mcp__<サーバー名全体>__*` と書く必要がある。エージェント定義の `tools:` も同じ扱いになる
  - `UserPromptSubmit` フック: スキルやカスタムスラッシュコマンドが展開される前に走るようになり、フックが止めればスキルに埋め込まれたシェルコマンドも実行されない
  - プラグインのフック: フックに渡せない、または応答が返らない操作は通さずに拒否する
  - リダイレクト: claude.ai のコネクタプロキシと Anthropic ホストの MCP サーバーへのリクエストは HTTP リダイレクトを追わなくなった
  - クラウドセッションと Remote Control の MCP コネクタは、既定で MCP プロトコル `2026-07-28` を交渉する。`MCP_PROTOCOL_NEGOTIATION=legacy` で旧方式に戻せる
- 既存の設定に効く変更（2.1.300）
  - `updatedInput`: PreToolUse と PermissionRequest フックの `updatedInput` は未知のキーが落とされ、ツールが受け付けない入力は呼び出しの拒否になる
  - `claude remote-control` の `--sandbox` / `--no-sandbox` を削除し、渡すとエラーで終了する。サンドボックスは設定の `sandbox.enabled` で指定する
  - api.anthropic.com への大きいリクエストは、テレメトリを切っていても gzip 圧縮される（`CLAUDE_CODE_GZIP_REQUEST_BODIES=0` で無効）
- 新機能
  - アイドル時の圧縮: 20万トークン以上の会話を約54分放置すると、1時間のプロンプトキャッシュが切れる前に自動で圧縮する。下限は `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`、無効化は settings.json の `"idleCompaction": false`
  - `CLAUDE_CODE_DISABLE_FILE_MENTIONS`: `@` で指定したファイルの中身を渡さず、パスだけを渡す
  - Claude Platform on AWS で `/advisor` が使える。モデルを選ぶまで advisor は動かない
  - OpenTelemetry: `api_request` イベントにキャッシュ書き込みを寿命別に分けた `cache_creation_5m_tokens` / `cache_creation_1h_tokens` が加わり、トレースのスパンに GenAI セマンティック規約の属性が付く
  - Claude in Slack（Claude Tag）: Slack Connect チャンネルで答えられるようになった（既定は無効）。承認が要るコネクタ操作では本人だけに見える許可カードを出す

- https://code.claude.com/docs/en/changelog
- https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md

### 2. [新機能] Anthropic が Messages API と Managed Agents の OpenTelemetry トレース出力をベータで始めた — Claude Platform 上のエージェントも、Claude Code と同じ監視基盤で追えるようになった

**要点**: Anthropic が 10/14 に、Messages API と Claude Managed Agents のリクエストを OpenTelemetry のトレースとして外部の監視ツールへ送れるようにした。これまで OTel で追えたのは Claude Code と Cowork だけで、自前のエージェントはアプリ側で計装する必要があった。

**詳細**:

- 設定: Messages API と Managed Agents は Claude Console で送信先を追加する。Claude SDK（Python / TypeScript / C# / Go / Java / PHP / Ruby）はスパンを自動で出す
- 中身: エージェントのターン、モデル呼び出し、ツール使用、MCP サーバー呼び出しを、レイテンシ・トークン数・ID つきの標準トレースとして送る。OTLP エンドポイントを受け付ける任意のツールで読める
- 提供状態: パブリックベータ。料金の記載は無い
- 事例として Ramp が、トレースを採点する自社システムで一部エージェントのトークン使用量を10〜20%減らし、セッションを30%速くしたと書いている

- https://platform.claude.com/docs/en/release-notes/api
- https://claude.com/resources/articles/agent-observability-on-the-claude-platform
