### 1. [破壊的変更+新機能] Claude Code の npm `stable` が `2.1.304` から `2.1.308` へ進んだ — stable に固定している組織にも `allowedMcpServers` の緩和が届き、API バージョン移行のコマンドが入った

**要点**: Anthropic が 10/21〜10/22 に Claude Code `2.1.307` / `2.1.308` を出し、npm の `stable` / `latest` / `next` がそろって `2.1.308` になった。10/20 の `2.1.305` で入った「`env` だけで `${VAR}` を使う stdio サーバーを `allowedMcpServers` で絞らない」変更は、これまで `latest` 側だけの話だったが、stable チャンネルの組織にも適用される。

**詳細**:

- `2.1.307` の追加
  - `/claude-api api-version`: Claude API を呼ぶコードを API バージョン `2026-10-21` へ移す（`temperature` などが 400 になる新バージョン。10-22 既報）
  - `claude_code.safety_event`: 権限ルール・auto mode・安全チェック・hook・サンドボックスがツール呼び出しを止めた、確認した、差し戻したときに、1件ずつ OpenTelemetry のイベントを出す
  - Code Review: `@claude review stop`（`off` / `pause` も可）で、PR の `@claude review always` 購読を新しいレビューなしで止められる
- `2.1.307` の挙動変更
  - `axScreenReader` と `CLAUDE_AX_SCREEN_READER` は、ユーザー・管理・`--settings` の設定からだけ効く（`2.1.305` 以降の扱い）。プロジェクトの設定に書いたものは無視される
  - セルフホストランナー: チェックアウト hook は既定で30分で止まり、セッションの準備が失敗する。長い hook は `--checkout-hook-timeout-min` を上げるか `0` にする
  - HTTP MCP のツール呼び出しが接続切れで二重に送られていた不具合を直し、再送は読み取り専用か冪等なツールに限った
- `2.1.308`（10/22 04:19Z）は「Bug fixes and reliability improvements」の1行だけ
- 前日の確認事項: 許可リストだけで MCP サーバーを止めていた組織は、`deniedMcpServers` に明記しないと更新後に読み込まれる

### 2. [料金+新機能] OpenAI が Decisions API（`v1/decisions`）を `gpt-6-luna` で GA にした — 分類・ルーティング・採点を出力課金なし・入力 $0.10/100万トークンで使える

**要点**: OpenAI が 10/22 に、型付きの判定（確率・選択・採点）を返す Decisions API を一般提供にした。10/6 のパブリックベータから、プロンプトキャッシュ・JSON 入力・1リクエスト400問（ベータは200問）が加わった。LLM アプリの前段の判定を、大手の API で本番に置けるようになった。

**詳細**:

- 料金: キャッシュなしの入力 **$0.10 / 100万トークン**、出力は課金しない。キャッシュの読み書きは `gpt-6-luna` の標準単価に従い、リージョン処理と長コンテキストの割増は掛かる
- 速さ: Responses API の約10倍としている
- ベータからの追加
  - プロンプトキャッシュ: 共通の入力を使い回して割引を受ける
  - 画像と JSON: 質問ごとに画像を付けられ、`input_json` で構造化データをそのまま渡せる
  - 会話履歴: メッセージに加え、関数呼び出しとその出力も判定の材料にできる
  - 運用: 組織の利用状況レポート、Private Link、GPT-Live からの直接呼び出し
- 対応モデルは `gpt-6-luna` だけである
- 比較: TypeSafe AI の Jev（`jev-1.13.0`）は入力 $0.042 / 100万トークン・出力無料で、同じ「文章を返さない判定 API」の形をとる。入力単価は Jev が約4割である

- https://developers.openai.com/api/docs/changelog
- https://developers.openai.com/api/docs/guides/decisions

### 3. [新機能] Anthropic が Claude Console で組織ごとに web fetch を止め、許可・拒否ドメインを決められるようにした — Managed Agents も組織の設定に従う

**要点**: Anthropic が Claude Platform の release notes の 10/20 の項に、管理者向けの web fetch 制御を書き足した（本日初検出）。これまで web fetch の可否は個々のリクエストやエージェントの設定で決まっていたが、組織の Capabilities ページで一括して止めたり、行き先のドメインを絞ったりできる。

**詳細**:

- 止めた場合: Messages API で web fetch ツールを含むリクエストは 400 になる。Managed Agents のセッションでは、`web_fetch` の呼び出しがエージェントにエラー結果として返る
- ドメイン制限: Managed Agents の `web_fetch` は、組織の一覧とエージェント側の `allowed_domains` / `blocked_domains` の両方を通った URL だけを取りに行く。リダイレクト先も判定する
- web search: Managed Agents は組織の「Allow web search」に 10/6 から、検索ドメイン制限に 10/14 から従っていた（今回はじめて明記された）
- 同じく 10/21 の項には、user profiles に `enforcement_status` / `enforcement_actions` が加わったと追記された。Anthropic がエンドユーザーを制限・BAN したかを読み、`enforcement_status[]` で一覧を絞れる

- https://platform.claude.com/docs/en/release-notes/overview
- https://platform.claude.com/docs/en/managed-agents/tools-web-restrictions
