### 2. [破壊的変更+セキュリティ] Anthropic が Claude Code `2.1.309` でサンドボックスと権限チェックのすり抜けを10件以上直した — npm `stable` はまだ `2.1.308` で、stable 固定の組織には届いていない

**要点**: Anthropic が 10/22 20:34Z に `2.1.309` を出し、`latest` / `next` が進んだ。シェルの起動ファイルがサンドボックスの外で実行される、`--mcp-config` のファイルを書き換えられる、などの抜け道を塞いだ。`stable` は `2.1.308` のままなので、stable チャンネルの組織は修正が来るまで旧挙動で動く。

**詳細**:

- サンドボックス・権限の修正（抜粋）
  - macOS / Linux: サンドボックス内の Bash の前に、シェルの起動ファイルがサンドボックスの外で実行されていた
  - macOS: シンボリックリンク経由のフォルダーに `denyWrite` の glob が効いていなかった
  - サンドボックス内のコマンドと自動承認の編集が、`--mcp-config` で渡した MCP 設定ファイルを書き換えられた
  - `Edit(path)` の deny ルールが、サブシェルを含むコマンドのリダイレクトを止めていなかった
  - worktree 分離のセッションが、ロケール接頭辞つきのコマンドと zsh の算術コマンドを通していた
  - Linux: セッション後も動くバックグラウンドコマンドで、サンドボックスの書き込み拒否が外れていた
  - Windows: 追加引数つきの `Set-Location` / `cd` が自動承認されていた
- 挙動の変更
  - `claude ultrareview`: ワークスペースの信頼が必須になった。端末では確認を出し、それ以外は拒否する。スクリプトは `--trust-workspace` を付けるか `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1` を設定する
  - `sed -i`: 編集プレビューではなく通常の Bash の確認を出してそのまま実行する。`/rewind` では戻らなくなった
  - Desktop と VS Code の bypass permissions モード: 危険な `rm` / `rmdir` は確認を出さずに即拒否し、書き換えのヒントを返す
  - `/claude-api` スキル: Managed Agents のサブエージェント構成を `coordinator` ではなく `multiagent_20261001` で組む

- https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md
- https://registry.npmjs.org/@anthropic-ai/claude-code

### 3. [新機能] Anthropic が Claude Enterprise でチャットと Cowork を1つの Claude に統合して GA にした — 管理者はロール別のモデル制限と「Efficient mode」で使えるモデルを Sonnet / Haiku に絞れる

**要点**: Anthropic が 10/23 に、Pro / Max では 2025年9月に済ませていた統合を Enterprise にも広げた。重い作業はクラウドの隔離 VM で続き、端末を閉じても止まらない。管理者向けに、ロール別のモデル制限・組織〜メンバー単位の支出上限・グループで共有する月額予算が加わった。

**詳細**:

- 管理者の設定
  - ロールアウト: Organization settings で管理する。既存の Enterprise 顧客には案内メールが届く
  - Model entitlements: ロールごとに使えるモデルを決める
  - Efficient mode: 統合環境で使うモデルを Sonnet と Haiku に限る
  - 支出上限: 組織・グループ・メンバーの3段で設定でき、グループには月額の共有予算を割り当てられる
- セキュリティ: エージェント作業は隔離 VM で動き、Enterprise では外向き通信（egress）が既定でオフ。コネクタの認証情報はサンドボックスの外に置く
- 料金: 従量課金のまま。エージェント作業はチャットよりトークンを多く使うと明記している
- 除外: Claude Code で ZDR を使う組織、HIPAA 構成、CMEK を使う組織は現在の構成のままとされる
- 既存のチャット、プロジェクト、コネクタ、スキル、プラグインは引き継がれる
