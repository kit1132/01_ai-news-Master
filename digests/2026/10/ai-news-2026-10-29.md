### 1. [料金+新機能] GitHub が GitHub Enterprise の全ライセンスユーザーに Copilot を含める契約形態を始め、Actions の無料枠をドル建ての共有枠に変えた — 「Copilot の席数を買う」前提が、「Enterprise の予算に対して初回リクエストから従量で引く」前提に変わる

**要点**: GitHub が 10/28 に、GitHub Enterprise Cloud の契約に Copilot を含め、AI 利用は初回リクエストから Enterprise 予算に従量で課金する形態を営業経由で始めた。席ごとの月次 AI クレジットは無い。同日、Actions の無料枠は分数からドル建ての共有枠に変わり、cloud sandbox の課金は11月に始まる。

**詳細**:

- Copilot 込みの GitHub Enterprise
  - 対象: GitHub / Microsoft の営業担当がいる GitHub Enterprise Cloud。新規契約・既存契約の移行とも営業経由。セルフサーブは段階的に開放し、日付は「数週間以内」に出す。現行のセルフサーブ契約は変わらない
  - 機能: Copilot Enterprise と同じ機能・モデル。ただし席ごとの月次 AI クレジットは含まない
  - Enterprise ライセンスの無いユーザー: Copilot Standalone（**$10/ユーザー/月**）で同じ利用ができる
  - 予算が尽きたとき: コード補完と next edit suggestions は使い続けられる。Copilot Chat・code review・cloud は予算が要る。席そのものは外れない
  - Copilot Business / Copilot Enterprise は引き続き購入できる
- Copilot の cloud 体験（同日 GA・有料プラン）: セッションは既定で cloud sandbox で動き、github.com・GitHub Mobile・CLI・Copilot アプリ・VS Code・Slack・Teams の間で引き継げる。アクセスは「Copilot in the cloud」ポリシーで管理する
  - Actions の無料枠: 標準ランナーの分数から、標準ランナー・cloud sandbox・（Team / Enterprise Cloud の）大型ランナーで共有するドル建ての枠に変わった。製品ごとの単価は従来どおり
  - cloud sandbox の課金は **2026年11月**に始まる。それまでは共有枠から引かれる

### 2. [新機能+仕様] GitHub が Copilot code review の承認を GA にし、Copilot の承認がリポジトリの必須承認数に数えられるようにした — 「必須承認は人が出す」前提が、管理者が有効にすれば Copilot が1人分を出せる前提に変わる

**要点**: GitHub が 10/28 に、Copilot code review がマージ可能と判断した PR を承認する機能を GA にした。有効にすると Copilot の承認がブランチの必須承認数に数えられる。既定はオフで、Enterprise・Organization・リポジトリ単位で有効にし、承認してよいファイルパスも絞れる。

**詳細**:

- 承認（GA）: 新しいコミットが push されると承認は取り消され、再レビューで新たに承認する。各レビューの PR 概要コメントにマージ可否の判断が載る
- Max（public preview）: Lite / Balanced に続く3段目のレビュー強度。複数プロバイダーのモデルで独立したレビューエージェントを走らせ、集約エージェントが1つのレビューにまとめる。時間と AI クレジットは Lite / Balanced より多くかかる（量は非公表）
- 管理: 既定のレビュー強度を PR・リポジトリ・Organization・Enterprise の各単位で決められ、上位の単位で上限の強度を決められる
- 対象プラン: Copilot Pro / Pro+ / Max / Business / Enterprise

- https://github.blog/changelog/2026-10-28-copilot-code-review-merge-with-confidence-with-max-and-approvals

### 3. [破壊的変更+新機能] Anthropic が Claude Code `2.1.312` で、Bedrock / Vertex / Foundry / Mantle の未知のモデル名（独自のデプロイ名や推論プロファイル ARN）に短いシステムプロンプトを使うようにした — 中身が Sonnet や Haiku でも、独自名で呼ぶ組織は何もしないとプロンプトが縮む

**要点**: Claude Code `2.1.312`（npm 10/27 publish・`latest`）が、クラウド経由の未知のモデル名に短いシステムプロンプトを使うようにした。元に戻すには `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` が要る。同じ版で Claude apps gateway が `sub` 以外の id_token クレーム（Entra ID の `oid` など）で人を識別できるようになった。

**詳細**:

- 組織の設定に関わる変更
  - `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0`: 未知のモデル名でも完全なシステムプロンプトを使う
  - `CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1`: フラグ付きメッセージ後の自動モデル切替が未知のモデル名にも掛かるようになったので、止めるときに使う
  - `oidc.user_id_claim`: Claude apps gateway で利用者を識別する id_token クレームを指定する
  - VS Code 拡張からサインインした後、管理設定と組織ポリシーがセッションの残りで取得されなかった不具合を直した
  - OpenTelemetry の `claude_code.safety_event` を送らなくなった。公式マーケットプレイスのプラグインが宣言した固定 URL のリモート MCP サーバーは `mcp_server.name` に実名が入る（従来は `custom`）
- 動作の変更: prompt / agent hook はサブエージェント込みでセッションあたり同時24本まで（timeout を超えて待つものは別に12本まで）。1秒未満の `timeout` は1秒として扱う。サブエージェントの `autoCompactWindow` は `CLAUDE_CODE_AUTO_COMPACT_WINDOW` の窓を下げる方向にだけ効く。利用上限の表示は「session limit」から「5-hour limit」に変わった
- 修正: サブディレクトリの大きな CLAUDE.md・rules ファイルを先頭だけ見て上書きしていた不具合を直し、Write は全体を読むか部分編集するよう促す
- npm は `{stable: 2.1.308, latest: 2.1.312, next: 2.1.312}`
